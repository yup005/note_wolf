# 本地数据库备份与隔离恢复

这是 BETA-010 的本地运维工具，支持 macOS/Linux 的 POSIX 私有目录。只由具有服务器文件访问权的运维人员执行；应用内的房主或管理员不会因此获得下载数据库、私人笔记或进行中身份的权限。没有新增 HTTP 接口。

## 生成与核验备份

从项目根目录运行，所有源文件都必须明确指定；命令不会默认读取 `.data/lobby.db`。

```bash
npm run --silent db:backup -- --source /absolute/private/data/lobby.db --output .backups/snapshot.sqlite
npm run --silent db:verify -- --source .backups/snapshot.sqlite --sha256 <生成时返回的64位摘要>
```

将尖括号内容替换为实际摘要，不保留尖括号。成功时输出一行 JSON，包含操作、文件路径、SHA-256、文件大小与数据库版本；失败时输出固定诊断并返回非零状态，不输出数据正文、原始 SQL 异常或堆栈。

运行中的数据库使用 SQLite 一致性备份接口，包含已提交的 WAL 数据，不复制尚未提交事务。仅在备份副本中整理为无需 WAL 附件的独立文件；不迁移、清理或改写源库。备份默认使用30秒预算，可用 `--timeout-ms 60000` 显式调整为1–300000毫秒。预算在备份进度及阶段边界检查；文件操作或单次SQLite同步校验结束后才能检查，不保证硬性的墙钟返回上限，SQLite锁等待另有上限。持续写入或磁盘错误可导致本次失败，不能将失败输出当作有效备份。

SHA-256应单独保存在受保护的运维记录中。`db:verify`可省略摘要检查文件结构、完整性及外键并计算摘要，但这不能证明文件来自之前记录的可信备份。

## 恢复到新文件并隔离检查

```bash
npm run --silent db:restore -- --source .backups/snapshot.sqlite --output .backups/recovery/lobby.db --sha256 <原先独立保存的64位摘要>
```

恢复必须提供摘要，先验证复制后的实际字节、SQLite完整性、外键及核心表所需字段类型/主键/必要唯一键，再发布新文件。运行中的 WAL 数据库不能直接作为恢复归档；应先用 `db:backup` 生成独立文件。目标、符号链接、硬链接或目标的 WAL/SHM/journal 附件只要存在就拒绝，不能用此命令覆盖运行库。两个操作争用同一目标只有一个能成功。

命令不启动服务器、不切换 `WOLF_DB_PATH`，不自动替换原库。用新文件进行隔离核验，确认账号、席位、阶段、官方事实、发布历史、私人草稿及收藏符合备份时点；正式切换应先停止写入并另行制定切换及回退步骤。恢复会回到备份时点，之后的修改、删除、密码/会话和分享撤销不会自动并入；旧会话、旧分享或已删除内容可能随旧快照返回。正式恢复前须确认安全回收与重新登录方案，本次不自动启用这些旧状态。以后启动恢复副本时，既有24小时房间清理、VIP到期及权限规则仍会执行；文件恢复不等于承诺任意旧实时对局都能继续。

## 存储与文件保护

- 新建目录权限0700，文件0600；已有目标目录也必须没有组/其他用户权限。权限不合要求时换用私有目录，不自动放宽已有目录。文件存放在任何 Web 静态目录之外。
- `.backups/`已加入忽略规则。数据库备份含账户密码散列、会话/分享凭据、身份、私人笔记等完整私密数据；不放进 Git、公开附件、后台下载或普通共享盘。此工具不提供加密或异机上传，文件权限不是加密。
- 输出只在完整校验并关闭/刷新文件后独占发布；可捕获的失败清理本次私有暂存目录，保留源和已有目标。进程被强杀或机器断电后可能留下权限受限的 `.wolf-snapshot-*` 暂存目录，不能据此认定备份成功；核验后由运维处理自己的残留文件，不批量删除其他备份。
- `PUBLISH_UNCERTAIN`表示文件已生成但目录持久写入未确认，先用校验命令核对，不自动覆盖重试。输出摘要不等于异机持久保存；目标盘损坏仍可能丢失副本。

## 当前验收边界

本地自动化仅使用临时合成数据库：真实 WAL/未提交事务、逐表数据比对、账号/活跃座位与私密夜间阶段、官方事实/多版本发布、私人草稿/收藏、恢复后独立写入、摘要/坏库/外键、路径冲突/并发/超时及实际 CLI。

正式持久存储、异机/加密备份、执行周期、保留与删除策略、恢复目标和线上恢复演练仍待配置；不配置定时任务、不迁移线上数据、不部署 Render。BETA-010为部分实现，不能以本地恢复测试代替正式生产恢复或真实设备验收。依据见[GAP-06](GAP_ANALYSIS.md#gap-06上线备份恢复与诊断仅有部分基础beta-010011)、[当前验证报告](TEST_REPORT.md)和[产品确认来源](PRODUCT_DECISIONS.md#local-backup-delivery-2026-10-15)。

实现依据：[SQLite Online Backup](https://sqlite.org/backup.html)、[better-sqlite3 backup API](https://github.com/WiseLibs/better-sqlite3/blob/master/docs/api.md#backupdestination-options---promise)。工具使用当前项目已安装依赖，不新增外部服务。
