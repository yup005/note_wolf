# VIP 对外复盘链接

沿用详细需求 V1 8.4、9.2 及用户手机优先、直接执行的授权。本轮只实现对外只读分享；评论、通知、头像与高级收藏分开交付。

选择服务端随机链接而非下载快照或客户端 URL 编码内容：可以每次访问核验撤销、作者撤回、账号禁用及 VIP 到期，并跟随最新已发布版本。已有记录档案独立于房间，因此房间删除后仍能访问有效分享。

- 登录且有效 VIP 的作者可给自己已经结束、已发布的帖子生成链接；普通房主不自动获得 VIP。分享其他作者的帖子本轮不开放，这不是新玩法规则。
- 链接为32字节随机值，持有者匿名只读。明确生成按钮说明其公开本局身份及已发布内容。仅输出发布版本的作者显示名、房间号、版本、结果、身份、文档；不输出账号ID、参赛访问名单、草稿、内部日志、管理接口或历史版本索引。
- 一个帖子保留一个当前链接。首次创建可重试；重新生成必须使用当前链接修订号，旧链接永久失效。主动撤销保留撤销状态；恢复 VIP 或重新发布不会复活旧链接。到期、取消 VIP 或禁用账号暂时不可读，恢复资格后未撤销链接可恢复。
- 未发布、进行中或撤回帖子没有公开正文。作者保留查看链接状态及撤销能力，即使 VIP 到期；只有有效 VIP 能生成或重新生成。
- 官方及个人分享都读取最新主动发布版本。仅保存或提交官方更正不公开私人草稿；主动发布后既有分享地址展示修订结果。按8.4保留“仅主动发布同步”的隐私边界，不把9.2解释成公开未发布推理。
- GET `/api/records/:id/share`、POST同路径 `{action:create|regenerate|revoke,revision}` 均真实会话及作者鉴权，严格拒绝伪造owner/token/版本参数。GET `/api/shared-records/:token` 仅允许当前有效链接，不支持历史选择。对外不可用均返回统一404，避免暴露账户或撤回原因。
- SQLite新增record_share_links，与accounts和record_drafts关联，无房间级级联删除。共享正文不存副本、不进入公共Socket频道。schema14迁移保留全部原有表数据。
- 复盘弹窗给作者提供「对外分享」折叠控件、状态、可手动复制的地址、撤销及重新生成。`/share/:token` 独立手机页面不初始化游客会话或游戏Socket，允许纵向阅读赛后内容；不改变对局一屏布局。每30秒及回前台复核有效性，失败清除正文。
- 首页登录后提供独立「我的分享」入口，GET `/api/shares` 仅返回本人链接与档案元数据。复盘撤回、取消收藏及删除房间都不移除管理入口；不通过读取撤回正文恢复权限。此项来自独立审查的遗漏修复。

验收：普通 / 游客 / 非作者 / 超管越权拒绝，未结束与草稿不外泄；VIP到期取消恢复、账号禁用恢复、撤回再发布、撤销与重新生成；并发修订和重复创建；服务重启及房间删除；匿名HTTP、严格参数、旧会话撤销、最新发布 / 未发布隔离；Chrome手机视口下生成、复制回退、独立访客阅读、失效清除及刷新。真实iPhone仍单列未测试。
