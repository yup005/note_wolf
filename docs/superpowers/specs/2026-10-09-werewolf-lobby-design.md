# 狼人杀房间大厅：设计审阅稿

## 目标与规格评估

面向线下面杀玩家，移动端优先、白色浅灰模块化卡片。本次交付范围为本地运行基础、创建四位数字房间号、OTP 加入、选择 12 个座位及多浏览器实时同步。VIP、评论、社交、发牌与游戏结算不在第一阶段。

G-001、S-004、UI 原则及 ROOM-01～04 足够支持大厅核心。完整自动法官尚被 R-01/X-02/X-03、D-02、H-02 等阻塞，不能把测试清单视为已通过。所有缺口见 OPEN_QUESTIONS.md；后续实现不得默认补齐。

## 方案比较

推荐 React + TypeScript / Node.js + Socket.IO / SQLite 单实例：开发与本地多设备验证直接，支持事务占座和后续持久化；扩为多实例时替换房间存储和广播适配器。

备选 Cloudflare Durable Objects：按房间串行与实时连接自然，但本地与部署绑定更强。备选托管数据库实时订阅：搭建快，但座位事务与细粒度私密投影仍需后端，当前引入外部依赖收益有限。

## 模块边界

- apps/web：React 移动界面、四格 OTP、房间大厅、连接状态；不作最终授权判断。
- apps/server：HTTP 命令入口、Socket.IO 订阅、会话校验、错误映射、连接管理。
- packages/domain：Room/Seat/Member 与纯业务校验、BoardDefinition、RuleDecision；不依赖 UI 或网络。
- packages/contracts：输入校验、命令、公共快照及错误码。
- packages/storage：SQLite 事务、房间号唯一约束、设备会话及迁移。
- 后续 game-engine：服务器状态机、可注入时钟与随机源、私密行动及规则策略。

公共房间投影与座位私密数据、官方对局事实、最终行动、管理审计、复盘修订分离。第一阶段不创建角色数据；后续禁止把完整内部状态广播给客户端后再隐藏。

## 数据与授权

roomId 使用独立随机标识；roomCode 为保留前导零的四位字符串，数据库唯一，冲突重试，号码耗尽明确报错。roomCode 仅用于查找，不赋予管理或座位权限。

服务器签发随机设备会话，以 HttpOnly cookie 持有；同源 HTTP 和实时连接共用会话。hostMemberId 独立于 seatId，房主选择座位后仍是同一成员。游客房主创建前仅提醒一次无法跨设备恢复管理权限；不生成房主恢复码。登录和跨设备恢复在后续独立阶段实现，本阶段不得冒充支持。

座位占用由数据库事务与唯一约束完成，同一成员最多一个座位。两个请求竞争同一座位，只允许一个成功；失败方收到 SEAT_TAKEN 并同步最新状态。断线、刷新不自动释放座位。换座/退座权限尚未确认，使用 unresolved 策略预留。

## 请求与同步

创建/加入/占座经服务器校验后提交事务，递增 roomRevision，广播公共完整快照。订阅前检查成员资格，加入房间后返回快照，刷新和重连重新取当前快照。客户端丢弃旧版本；服务器处理消息重复不能产生第二个成员或座位。

公共快照只含房间号、板子、12 个座位显示名和占用状态、房主公开标记与 revision。会话令牌绝不放入广播。预留 outbox 防止提交后广播失败导致状态遗漏；本地单实例可用事务后广播加重连拉取恢复。

## 界面

首页含昵称、创建按钮及四格数字 OTP，支持逐格输入、回退、粘贴和四位完成后查找。创建房间呈现游客提醒。大厅含房间号卡片、固定板子说明、12 座位网格、本人座位状态与连接状态。占用座位禁用；错误在界面可见并可重试。屏幕阅读器可识别每格号码和座位；按钮至少 44px。手机至桌面布局自适应。

## 分阶段实施与验收

1. 工程基础：workspace、TypeScript、开发脚本、数据库迁移与 README；验证安装、类型检查、服务器健康检查及构建。
2. 领域与存储：四位号码分配、成员授权、首次占座；单元/数据库测试 ROOM-01～04、号码冲突、耗尽、无效座位与并发占座。
3. 传输层：HTTP 与实时订阅；真实服务多客户端测试创建/加入/选座广播、未授权订阅、重复请求、断线重连、服务重启恢复。
4. 移动界面：完整流程；独立浏览器上下文测试创建、OTP 粘贴/删除/前导零、加入、选座、竞争与刷新。
5. 综合验收：至少三个独立浏览器上下文实时同步，12 人容量与错误路径；记录执行结果及验证局限。真实手机需同一局域网访问 0.0.0.0 服务，跨公网联机属后续部署。

每阶段完成后执行对应测试，失败先定位，不能以静态截图或模拟 UI 代替实时同步证据。尚无实际执行结果，本文件仅为设计。

## 后续 MVP 顺序

大厅通过后再做发牌与私密权限；确认 P0 规则后实现自动法官状态机；随后房主公开控制与基础官方复盘。每阶段建立独立测试边界，未裁决路径显式阻止执行。SQLite 单实例为首阶段限制，未来多实例需共享事务存储和广播适配。
