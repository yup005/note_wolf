# M2 durable engine framework

Date: 2026-10-10. Scope: COPY-001 / WIN-001 framework in the [M0–M6 specification](../../CODEX_MECHANICAL_BOARDS_IMPLEMENTATION.md), after [M1 configuration](../../MECHANICAL_IMPLEMENTATION_PROGRESS.md). This turn ends at M2; new boards remain gated before dealing.

## Models and boundaries

- `contracts/abilities.ts` holds reusable validated ability/copy/use schemas; `domain/skills.ts` keeps its existing copy/use API. JSON parameters can contain nested structures. Copies freeze the source snapshot, restore full capacity, reset uses/lastTarget and retain immediate source/skill/night. True role and camp stay separate from mimicked role.
- `contracts/engine.ts` models formatVersion1, room board/rule version, true players, public-role/vote/interjection state, private learning source/time and mixer model, locked actions, per-source effects, deduplicated deaths and victory. Public-state fields model later projection; no full engine state is a public projection.
- `domain/engine.ts` validates composition/camps/seats, learning/copy provenance and capability parameters, timing/use history/inventory, action references and resolution/death/victory consistency. Persisted expected copies must exist; null provenance cannot evade validation. Pre-depleted source inventory is permitted, but recorded uses cannot exceed spent charges or replenish them. Original optional lastTarget remains compatible; a supplied value must match latest recorded use.
- `appendNightAction` derives caster true role/ruleset/night, checks living targets and owned skills, enforces server-derived normal/inherited knife authority, consumes inventory once and rejects conflicting retries. It does not kill anyone. `copyEngineAbilities` freezes learning once from another living player; callers still supply the confirmed ability profile/timing. Authenticated actor selection, role grants, per-night limits and exact phase legality belong to the M3–M5 orchestrator.
- A `ResolutionStrategy` must match board ruleset/version. Without a strategy, settlement is blocked with an explicit question ID. A product-decision result freezes collection and changes no life state. A settled result needs one outcome for each attack, source-consistent provenance and valid protection references; deaths retain all independent source effect IDs, are deduplicated, then evaluated by the shared victory module. Synthetic test strategies validate this contract; they do not implement actual guard/poison/antidote/reflection interactions.
- `storage/engine.ts` is an internal SQLite adapter with room/config validation and optimistic revisions. Unsupported formats, malformed JSON, invalid persisted revisions, overflow and inconsistent snapshots fail closed. It has no token-based read method, HTTP/admin route or public/voice projection. Existing Lobby/Night/Day runtime modules remain in place. Later orchestration will connect this adapter; current standard games keep their existing persistence.

## Confirmed rules and remaining decisions

Armor inherits all confirmed base rules unless explicitly overridden, per source commits ced569a / fab5566d. Ordinary simultaneous endings therefore use wolves priority; the former MA-VICTORY-SIMULTANEOUS blocker is superseded. Bonus knife requires inherited normal knife, one use, targets may match or differ. This framework checks inventory/authority without adding the armor damage algorithm.

Mixer private selection/timeout and inspection, mechanical idiot alive classification/extra-night priority, undefined damage/custom mechanism interactions and new-board witch self-save after night one remain blocked for dependent gameplay. Learning source death at settlement does not erase the copy. M3–M6 must integrate confirmed role behavior and privacy through existing boundaries, followed by full board/device acceptance.

`engine.test.ts` covers nested copy independence, learning time, locked/idempotent action provenance, no death at submission, explicit missing/product-decision blockers, independent damage evidence/death deduplication, inherited armor priority and corrupt state rejection. `engine-store.test.ts` closes and reopens a file database, restores learning/source inventory/lastTarget/actions and settled evidence, and checks stale writes/config drift/version/revisions. `engine-privacy.test.ts` persists synthetic secrets alongside a real isolated server and verifies host/player HTTP, socket subscription/broadcast and nonexistent engine endpoints. Final executed counts and publication evidence live in [stage progress](../../MECHANICAL_IMPLEMENTATION_PROGRESS.md). Physical iPhone and full new-board acceptance are separate and pending.
