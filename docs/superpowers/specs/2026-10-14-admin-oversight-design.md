## Outcome and approach

Extend the existing administrator panel with grouped report overview, searchable/filterable/exportable management metadata, unified operation history and public-share revocation with a required reason. Reuse existing moderation actions and public-record readers. A focused AdminOversightStore queries safe explicit projections, incorporates existing community audit as historical source, records actual VIP/status changes, and owns revoke receipts/cursors. Prefer this incremental extension over duplicating moderation or adopting a new dashboard framework. Root owns docs/full checks/current-main publication; source workers have disjoint ownership and run sequentially. User's standing do-not-ask/continuous implementation and current-branch publication instructions override repeated process gates and per-task commits, not privacy or unresolved gameplay.

## Privacy and source boundaries

All routes require a current active super-admin, including retries/export/cursors. The only admin sees public-ended metadata and authorized moderation evidence; oversight projections/CSV exclude comment/record bodies, unpublished notes, roles, night actions, source tokens, passwords/session data, and arbitrary JSON. Account IDs, comment IDs, record IDs, public nicknames, reason/action/status/time/count are legitimate administrative metadata. Existing report-body review remains in its original authorized component, not export. No new ongoing-game secret reader. No minted sessions, cross-user inbox access or bypass through supplied owner IDs.

Query nickname by literal substring (trimmed max80 Unicode), dates as epoch-ms inclusive from/exclusive to; UI converts local date start/next midnight, clear labels. Strict shape/safe integer and from<to. Stable descending timestamp/ID keyset cursors persisted/signed, bound to dataset + normalized filters, not limit. Default20/max50. Query changes clear cursor/items; paging dedupes. Existing historical rows are real sources, not fabricated earlier VIP/status logs. Metadata projection leaves source storage alone. Reads/exports do not acknowledge favorites/notifications or extend runtime-room retention.

## Fixed contracts and endpoints

New packages/contracts/admin.ts exports:
- AdminAuditAction = 'vip'|'status'|'share-revoke'|'dismiss'|'delete'|'warn'|'mute'|'unmute'.
- AdminFilter {q?:string;from?:number;to?:number;action?:AdminAuditAction;status?:'open'|'reviewed'|'active'|'paused'|'withdrawn'|'revoked'}; each dataset rejects irrelevant actions/status values; omitted means all.
- AdminAuditItem {id:string;at:number;operator:string;subject:string;action:AdminAuditAction;reason:string;detail:string|null}.
- AdminReportGroup {commentId:string;commentVersion:number;author:string;roomCode:string;latestAt:number;reportCount:number;openCount:number;reviewedCount:number;status:'open'|'reviewed'}. Group by comment across all reporters, exact distinct reporters; pending if any open. Counts always reflect whole group even when filtering group status/dates; time filter uses group's latest report time. No body/reporter names. Filter q matches author nickname, not hidden body; action not allowed.
- AdminShareItem {recordId:string;author:string;code:string;version:number;revision:number;updatedAt:number;state:'active'|'paused'|'withdrawn'|'revoked'}; current existing link metadata on ended published/nondeleted records only. No bearer. Author-disabled or VIP unavailable => paused, explicit revoked wins then paused then withdrawn then active. Query q matches author, status is link state, action not allowed.
- AdminPage<T> {items:T[];nextCursor:string|null}.
- AdminExport {filename:string;csv:string;count:number}.
- AdminShareRevoke {requestId:UUID;expectedAdminId:UUID;recordId:UUID;revision:nonnegativeInt;confirmed:true;reason:trimmed1..500Unicode}.
- GET /api/admin/oversight/reports, /audit, /shares -> corresponding AdminPage; strict query strings q/from/to/action/status/cursor/limit, dataset rules above; invalid keys rejected. Audit disallows status, q matches subject or operator nickname.
- POST /api/admin/oversight/export strict {kind:'reports'|'audit'|'shares',filter:AdminFilter} -> AdminExport. No cursor/limit; same filters/projection as list, all matching up to5000 rows; >5000 => EXPORT_TOO_LARGE/409, never silently truncate. BOM UTF8 + quoted CSV, doubled quotes and CRLF rows; neutralize formula-leading = + - @ and control/whitespace prefixes, including malicious nickname/reason. Client Blob download with controlled filename, revoke URL. No network navigation carrying credentials, no external service.
- POST /api/admin/oversight/share-revoke strict AdminShareRevoke -> {applied:true}. Same UUID/fullbody returns same receipt, altered reuse invalid. Current admin+expectedAdminId checked BEFORE receipts or writes. Revision mismatch STALE_SHARE/409. No link/non-ended/unpublished/deleted => NOT_FOUND; no read of draft contents. Already revoked same current revision produces no repeated audit/message. Original receipt retries after author regenerates never revoke new token; old new-request revision rejected. Reason and actual actor logged transactionally with link revoke + affected-account mandatory message. Author retains records/drafts and existing ability to explicitly regenerate a different link; this is not an account ban.

Lobby wrappers fixed: adminReportGroups(token,query), adminAuditList(token,query), adminShares(token,query), adminExport(token,input), adminRevokeShare(token,input).

## Storage and mutation integration

Add focused admin operation table storing actor/target identifiers + nickname snapshots, action/time/reason and safe textual before/after detail for VIP/status and revoke only; no secret state/body JSON. Direct AuthStore.setVip/setStatus calls must emit structured actual-change callbacks inside their existing transaction, not only HTTP wrappers, with actor from requireAdmin and safe before/after values. Existing optional notification callback remains unchanged. Repeated identical state writes do not add audit rows; callback failure rolls back state/notification/log together. For setStatus active->disabled keep session revocation and Socket disconnect behavior. Current account/VIP HTTP contracts remain compatible. Merge legacy community audit in unified projection with deterministic source-prefixed IDs and real stored reasons; preserve original evidence/history and timestamps, no duplicate import.

Share revoke mutation + audit + notification + exact receipt must be atomic. Validate active current admin before receipt replay, preserve admin/normal user session semantics, never operate as the source author. Ended metadata projection should work after runtime-room cleanup and with withdrawn/paused links. Expiry of notifications must not delete audit. Revoke makes original public/shared-favorite/comment/notification source unavailable without transferring original favorites/names/dates to a new token; this relies on existing original-link validation and gets regression coverage.
