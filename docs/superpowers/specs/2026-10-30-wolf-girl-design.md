# 12 人狼女孩板子设计（已批准）

日期：2026-10-30。需求来源：[GitHub Issue #9](https://github.com/yup005/note_wolf/issues/9)。
本轮 Owner 明确补充：**毒师允许首夜自毒；表白超时随机选择非狼人目标；狼女孩自爆后沿用普通狼下一夜优先指刀资格。**本文是实施设计，不代表已实现、测试通过或部署。

## 意图与范围

在线下面杀辅助应用增加一个官方固定模板：3 普通狼人、1 狼女孩、4 平民、预言家/毒师/猎人/守卫各 1。复用现有手机操作、房间/座位、发牌、自动法官、手动记录、暂停重连、秘密权限、赛后记录与发布体系。标准、机械及装甲板规则与旧数据继续兼容。

成功标准是能从准备发牌完成首夜及后续多昼夜到终局，并正确保存及隔离表白关系、独立个人胜负、废票及死亡原因。不能只交付角色标签或可选择但无法正常进行的模板。

不扩展九尾/白泽、混血儿榜样规则、机械复制狼女孩/毒师、任意混搭新角色、普通管理员秘密权限或生产部署。

## Approaches

采用在现有框架中增加 `wolf-girl` 规则分支的方案。继续共用存储、认证、日间通用流程与公共/私密投影；专属夜序、表白关系、自爆原子事件、胜负策略独立实现。该方案已由 Owner 于 2026-10-30 明确批准实施。

把新角色归入现有机械规则会继承错误夜序、复制和混子算法，不符合 Issue。另建完整游戏服务会重复现有权限、持久化和复盘功能，也不适合本仓库。因此保留现有架构、增加专属策略是合适路径。

## 现状与改动位置

- `packages/contracts/board.ts` 尚无狼女孩、毒师、对应 ruleset/preset；`boardConfig.ts` 目前把非标准且无装甲狼配置归类为机械通灵师，必须优先识别新角色。
- `packages/domain/night.ts` 对所有非标准板调用机械夜晚流程；新板必须显式分派，不能落入该默认分支。
- `packages/contracts/engine.ts` / `packages/domain/engine.ts` 已有角色真实身份、camp、技能库存、行动/结算/胜负快照，存储层已有重启恢复。表白采用独立字段和事件，不写入 `model` 或 `mixer`。
- `packages/domain/day.ts` 已在 `vote_result` 停留，房主继续后才结算放逐，适合作为投票后自爆窗口；不必先杀人再倒退历史。
- `canShoot` 当前神职分支可能仅按猎人身份允许开枪；新板明确按 `knife`/`exile` 白名单校验，报复死亡不可开枪。
- `packages/domain/victory.ts` 现有通用优先级为屠边先于灭狼，新板须按 Issue 1A 建立独立判胜分支，不全局修改旧板。
- `packages/storage/boards.ts`、前端板子/夜晚/白天/本人身份界面、公共播报、法官及补录、复盘投影和测试均需对应接入。

## 版本与模板

增加角色 `wolfGirl`、`poisoner`，ruleset `wolf-girl`，官方模板 `wolf-girl-12`。官方模板保持不可修改/删除，自定义副本为独立记录。

首版仅完整支持上述确定阵容及其自定义副本。使用新角色但不满足该阵容的配置明确显示未支持并阻止开局；不得静默切换机械策略，修改 UI 也不能绕过服务端校验。这是为避免未确认角色交互而提出的首版范围。

新增规则版本时兼容读取旧版本；已有房间保持原 ruleset、规则版本和配置快照，不因全局常量更新失效。若不需要全局版本更换，应保留现有旧版解析，另为新策略保存版本标识。具体兼容机制由实施者按实际引用选择并验证旧库恢复。

## 秘密状态与表白

可信内部状态保存：女孩座位、目标座位、表白夜次、是否接受/是否狼混、私密通知送达/确认状态及唯一事件标识。首夜表白阶段超时且本人尚未提交时，由服务端随机选择一个合法非狼人目标并保存关系；不能选择女孩自己或狼队友。此项由 Owner 本轮明确确认。超时处理与本人提交竞争时只接受一个结果，重连和再次推进不得重新抽选。后续夜不能重新发动。

真实角色始终不变。目标为平民时，个人胜负归属改为狼人，真实属性仍是平民，刀权为无、查验为好人、屠民仍包含该座位。目标为神职时身份、camp、技能及胜负归属不变。

女孩只收到行动已提交的统一回执，不获知接受/拒绝或目标角色。普通狼只认识狼女孩，不能读取目标。目标只有在通知阶段主动进入私密视图才能获知被表白；只有成为狼混的平民收到女孩座位，拒绝的神职不收到女孩座位。所有回执、错误、超时和重连响应不得泄露额外信息。

重试按请求/阶段标识幂等；重复相同请求不重复消耗，旧阶段或改目标拒绝。秘密状态仅自己和现任合法法官按现有权限读取，不进入公共 HTTP、Socket、语音或普通后台。

## 夜间流程与技能

首夜：守卫 → 狼女孩单独表白 → 狼队相认 → 毒师 → 预言家 → 猎人状态 → 被表白者私密通知。角色之间沿用 5 秒闭眼。首夜狼阶段客户端不显示刀口操作，服务端拒绝所有刀口提交及优先刀绕过。相认结束可确认但不能造成狼刀效果。

后续：守卫 → 狼队正常刀人 → 毒师 → 预言家 → 猎人状态。表白与首次通知阶段不重复；已经获知的关系可由本人按既有私密身份查看方式重新打开，不在前台自动暴露。

阶段序列公开且固定，不因角色死亡、库存或是否提交表白而改变。新增动作/通知阶段的时长先采用 30 秒作为工程建议；无人可操作时走虚拟窗口，不借提前跳过暴露存活。其他已有角色采用对应既有时长及确认结束行为。

毒师仅一瓶毒，无救药、无刀口信息。允许首夜以自己为目标；投毒对守护无视。后续夜自毒资格沿用同一目标校验，是本设计的建议默认，待审阅时可指出差异。保存毒药消耗，不因刷新、重试或后台切换返还。

守卫可空守、自守，不能连续两夜守同一座位；无机械弹毒。守护仅挡普通刀，不挡毒或报复。验人仅返回好人/狼人；普通狼人和女孩为狼人，狼混仍为好人。猎人仅因刀/正常放逐死亡有枪；毒或报复无枪，死因冲突以有效毒杀导致禁枪，与现行规则一致。

## 日间窗口、废票与原子自爆

普通发言、警上与 PK 的通用资格以 `OPEN_QUESTIONS.md` 已确认的 X-01/PK 规则为来源：警上允许、投票计时中禁止、警长 PK 候选自爆后仅剩一名候选时自动当选、放逐 PK 台上不得在发言阶段自爆。保留既有警徽顺延/流失处理。正式警长/警长 PK 投票结果不属于女孩废放逐票窗口。

女孩额外允许在 `vote_result` 且结果为放逐或放逐 PK、房主尚未继续时自爆。投票完成到继续生效之间为明确窗口，不新增竞速计时。普通狼人仍无此能力。窗口资格、回执及旧请求校验均由服务端执行，暂停期间不执行。

自爆事件按一个事务处理：校验 → 标记该轮放逐结果作废（如适用）→ 女孩死亡 → 仍存活的表白目标因报复死亡 → 合并尚待公告的有效夜间死亡并去重 → 完整事件后判胜 → 必要的警徽处理 → 未终局则进入天黑流程。

被表白者即使是拒绝的神职也被报复，已死则不重复杀死。女孩及报复目标不生成遗言或猎人枪任务；原来其他有效死者仍按其自身死因处理。女孩非自爆死亡不触发关系。不把白狼王的先判胜再选目标策略复用于该事件；报复必须在本事件判胜前完成。

Issue 的任一自爆均报复、双方无遗言优先于旧普通狼吞毒分支；不能因女孩已经中毒就静默套用白狼王的禁止带人例外。此处按 Issue 明文执行。**Owner 已确认女孩自爆后沿用普通狼 N-003 的紧接下一夜优先指刀资格。**仍须有存活且已相认的真实狼同伴、只限下一夜、成功警上吞毒不得指刀。继承资格不得使狼混获得刀权，也不得绕过终局。

保留不可变原始投票事件和追加的作废事件；公开结果、最终有效复盘不得仍显示被撤销的放逐为死亡。正常放逐已经生效后不再允许废票。并发自爆/继续由现有版本与事务保证只有先合法提交者成功。

## 终局与个人结果

只在完整夜间死亡批次或完整白天事件后评估。按 1A：真实狼人（普通狼与女孩）全部死亡即好人胜，狼混不阻止终局且个人判负。新板独立策略先检查真实狼人全灭，旧板同时屠边优先不扩展到此分支；这是对 Issue 1A 的直接解释，设计审阅时需特别核对。

仍有真实狼时，神全灭或平民全灭判狼人胜。平民集合按真实身份，包含接受表白者；无混血儿阈值。为狼混保存明确个人 `won` 结果，前端及正式复盘不能只用真实角色推算个人胜负。

夜间内部结算、首日警长/死讯发布采用现有首日通用顺序；公开前不泄露毒药、秘密目标或死亡。自爆发生时按该原子事件汇总尚未公开死亡后统一判胜，不能在连带死亡中途提前终局。

## 存储、法官、手动与回放

新增事件和专属状态进入现有可信序列化数据，校验读取与写入；覆盖夜转昼、昼转夜、服务重启及归档，不能只留在客户端或单晚内存中。事件区分表白、私密信息、毒药、守护、相认、有效狼刀、废票、报复及终局。

现任合法死者法官可看相关游戏秘密。法官补录按已发生事实录入表白关系、药/守历史和死因，核对后才切回自动；缺失关系、无法确认的库存或废票冲突阻止切回，不能猜测。独立手动记录仍不执行秘密技能；不能根据手动公开死讯自动推测狼混归属。

赛后身份/可信事实按现有参局与发布权限展示；本人未发布笔记不被合并到游戏事件。收藏/分享只显示最终有效的放逐和死亡，同时能够辨认废票，旧归档继续兼容。
