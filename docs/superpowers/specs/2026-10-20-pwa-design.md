# iPhone PWA 与安全恢复设计

状态：Owner在本设计交付后回复“继续”（2026-10-20），设计及两项明确取舍已确认；[实施计划](../plans/2026-10-20-pwa.md)已写出、待审阅，尚无产品实现。需求 PWA-001 原由 [Issue #4](https://github.com/yup005/note_wolf/issues/4) 确认；本聊天在 REMATCH-001 交付后按剩余 P1 优先推进。设计确认不等于已实现或真机验收通过。

## 目标与范围

HTTPS 站点可添加到 iPhone 主屏幕，以独立窗口运行。缓存只含构建时确定的公开静态资源；身份、房间、账号、私稿、分享正文及实时消息均由服务端重新授权。断网只显示联机提示，不提供离线对局、操作队列或推送通知。保留普通浏览器、现有同房多局和所有玩法权限；不部署、不绑定 Render 或其他平台。

成功包括安装元信息、明确的安装/更新引导、安全缓存和恢复流程，以及本地自动验证。Issue 的 iPhone 添加、重开、升级、切换账号和弱网条款仍须真实设备验收；Chromium 和模拟事件只证明相应自动化场景。

## 已核实的现状

- `apps/web/index.html` 有标题、viewport 与主题色，尚无 Manifest、安装图标、Apple 元信息或 Service Worker。`main.tsx` 直接挂载 App。
- `vite.config.ts` 使用现有 Vite/React 构建，产物为 `dist/web`；`apps/server/main.ts` 在生产模式提供静态文件及 SPA 回退，开发模式使用 Vite 中间件。尚无专用 Worker/HTML 缓存头或构建资源清单。
- `apps/server/app.ts` 已对 `/api/` 设置 `Cache-Control: no-store`；通用 `api.ts` 尚未显式设置 fetch cache。Socket 先验证会话，订阅回执只含公共房间快照。
- `useRoom.ts` 返回前台会重订阅当前房间，但不会重新读取账号与成员权限。`App.tsx` 的 `/api/session` 初始化主要发生在挂载时，不能单靠公共快照认定旧页面的账号、成员和法官权限仍有效。
- 身份卡、夜间/白天本人卡、法官、收藏及部分后台组件已有隐藏、代际或取消保护，但覆盖方式不同。`useSharedRecord.ts` 已用 no-store 与定期复核，复核开始时仍可能保留旧正文。不能把这些局部机制等同统一的恢复屏障。
- 同房多局已按 gameId/sessionRevision 隔离局内组件与语音；本设计复用这些边界，不改变服务器授权或旧归档 ID。

## 方案比较

| 方案 | 效果与代价 |
| --- | --- |
| 推荐：构建清单静态缓存 + 独立断网页 + 根级恢复屏障 | 明确可审计的缓存集合，断网不运行旧对局；统一处理大厅、房间、历史编辑、后台和分享。需要梳理恢复时的组件生命周期。 |
| 只加 Manifest、图标与安装说明 | 改动较小，但未实现 Service Worker 缓存，也未解决后台恢复时旧账号/身份/分享正文仍在页面的问题，不足以完成 PWA-001。 |
| 通用运行时缓存或完整离线 App shell | 能离线打开更多页面，但放大动态 URL、旧 HTML/JS 混用和缓存隐私风险；离线游戏不在本期。引入通用 PWA 插件仍需额外约束，不能靠默认策略保证本产品边界。 |

推荐第一种，不新增依赖是当前工程选择；若构建验证证明需要依赖，再单独说明理由。本期只缓存公开静态产物，不缓存在线首页 HTML，不缓存任何请求的账号或对局结果。

## 安装与显示

Manifest 提供稳定 `id` 和 `start_url` `/`、`scope` `/`、中文名称“笔记狼人杀”、`display: standalone`、语言及与当前页面一致的背景/主题色。提供 192、512 像素普通 PNG 图标和带足够安全边距的 maskable 图标；iPhone 提供 180 像素 Apple touch icon。图标沿用现有品牌狼头，不含用户或房间资料。HTML 增加对应链接、Apple standalone 与标题元信息；viewport 保留缩放能力，并适配安全区。

首页提供按需打开的“添加到主屏幕”说明：iPhone 引导用 Safari 打开、分享菜单、添加到主屏幕。已处于 standalone 时不再提示安装；其他浏览器说明使用其安装菜单或 Safari 路径，不伪装成系统弹窗，也不把 iOS 没有触发安装事件当作失败。不自动弹窗打断加入房间或对局。

Service Worker 只在生产构建、同源安全上下文且浏览器支持时注册；注册失败或能力缺失不阻止正常联网页面。localhost 仅作为隔离测试的浏览器例外，不声称公网 HTTP 可安装。开发服务器不注册 Worker，生产测试使用独立端口和全新浏览器上下文，避免与开发作用域混用。

## 缓存与导航边界

Vite 构建阶段生成确定的资源白名单及内容摘要版本，Worker 自身不依赖运行时接口。只收录本次生成的哈希 JS/CSS、指定安装图标和无个人内容的 `offline.html`；Manifest 单独联网读取，不进入 Worker 缓存。不按“后缀像静态文件”或用户请求自动扩充缓存，不收录 source map、构建诊断、任意 public 文件或整套语音目录。

| 请求 | Worker 策略 |
| --- | --- |
| 白名单中的同源 GET 静态资源，且无查询参数 | 本版本静态 cache-first；缺失时仅对该资源联网，不把任意响应写回缓存。安装阶段检查成功、类型和无重定向；不接受 API/SPA 回退伪装成 JS/图标。 |
| 在线文档导航，包括 `/` 与 `/share/<token>` | network-only，文档响应 no-store；网络不可用时返回固定静态断网页。导航 URL、token、HTML 和分享正文不写 Cache Storage。 |
| `/api/`、头像、Socket.IO、语音动态请求及所有非 GET | 完全不进入 Worker 缓存逻辑，沿用真实网络、凭据和授权；不合成成功或离线结果。API 保留服务端 no-store，通用客户端也显式 no-store。 |
| 未列出的静态 URL、带查询参数请求、跨源请求 | 不缓存，交还浏览器原有网络流程；不读取其他应用缓存。 |

安装时使用固定白名单，公开静态请求不带会话凭据；响应若失败、重定向、类型不符或声明 no-store，本次安装失败，不激活半套资源。允许网络照常运行并保留原版本，不回退到扩大缓存范围。静态路由必须准确命中，缺失 `/sw.js` 或清单静态文件返回错误，不能被 SPA fallback 返回 index.html。

`/sw.js` 使用正确 JavaScript 类型和 no-store；Manifest、在线 HTML 使用 no-store。白名单中的固定断网页是无个人内容的独立静态文件，允许公开缓存；白名单哈希静态文件可长缓存，图标仍由版本化 Worker 清单更新。服务端文件规则放入独立前端静态服务模块，供生产入口与生产模式测试共用；不改 `/api` 的认证、限流或响应内容。

断网页只含品牌、无法联机说明、重试和返回首页入口；无账号名、房间号、角色、私稿或历史页面。重试重新请求当前导航，不提交任何游戏动作。首次从未在线访问且缓存尚不存在时，平台自身网络错误仍可能出现，不承诺首次离线可启动。

## 更新与多窗口

缓存名使用本应用专属前缀和内容摘要，摘要覆盖白名单资源及 Worker 策略模板；相同构建产生相同版本，不把时间戳或个人数据作为版本。安装新 Worker 先建立完整的新缓存，失败删除本次未完成的新缓存，不破坏当前缓存。激活只清理本应用旧版本缓存，绝不调用全站缓存清空。

本期选择浏览器原生等待激活：不调用 `skipWaiting` 或 `clients.claim` 强制抢占正在使用的页面。检测 waiting/updatefound 后以非模态提示说明“新版本已准备，请先保存笔记，关闭本站所有窗口后重新打开”，可稍后处理；不把单次刷新宣称为必然完成更新。所有旧受控窗口关闭后由浏览器激活新版本，再清旧缓存，避免旧页面继续加载已删除的旧分块。

首次安装激活时不自动刷新。新旧版本测试必须包含两个受控窗口：任一旧窗口仍打开时不抢占、不删其缓存；全部关闭并重开后使用新版本。多窗口使用原有共享 cookie；不引入账号 token 的跨窗口广播。若未来需要“立即更新”，另行设计未保存编辑、多窗口与旧构建资源兼容，不能在本期偷偷加入强制激活。

## 权限恢复与私密生命周期

推荐在 `main.tsx` 与现有 App 之间新增根级恢复边界，覆盖大厅、账号/后台、房间、历史笔记、收藏/通知及分享页，而不是仅给身份卡加一层遮罩。状态为 `checking / ready / hidden / offline / failed`；仅 ready 可挂载业务子树。恢复只读请求沿用分享读取的6秒超时，可人工重试；不为超时自动重放写操作。

1. 初次加载先显示无个人内容的“正在连接”界面。大厅路径以 no-store 读取 `/api/session`，使用返回的当前账号、成员和公开房间列表初始化 App；原记住房间只作导航提示，已失权或已清理时回首页，不拼接旧 `me`。
2. `visibilitychange` 变为 hidden、`pagehide` 或浏览器 offline 时，同步标记根内容不可显示、不可交互，递增恢复代际并卸载业务子树。组件清理停止音频、断开旧 Socket、释放语音租约和取消私密读取；同步隐藏不等待 React effect，避免 BFCache 留存可读的旧页面。
3. 回到 visible、`pageshow`（含 persisted）或 online 后，合并同一轮恢复事件，再发新权威请求。请求未成功前不显示旧 DOM；超时、401/403、无权限、弱网失败只显示可重试界面。`navigator.onLine` 只作提示，最终依真实请求结果；在线事件本身不代表恢复成功。
4. 成功后以新的恢复代际挂载业务子树。当前 gameId、成员、法官任职、VIP和管理员身份来自新响应；局内私密内容沿用原入口重新读取和原查看操作，不能把上次已揭示的卡自动恢复。`useRoom` 重新订阅公共状态，订阅成功前局内动作仍禁用；公共快照不能替代会话复核。
5. 退出或切换账号成功时，先使旧渲染代际失效，再按真实会话结果挂载新子树。另一个窗口改变 cookie 后，旧窗口下次恢复必须重新取权威状态。旧读取、旧房间动作、旧恢复请求即使迟到成功也只能落在失效代际，不得更新新子树。挂载失败不能重新露出旧账号界面。
6. 分享页不以“游客会话有效”代替链接授权：先重新读取实际 `/api/shared-records/<token>`（保持既有匿名 credentials omit），验证成功后才显示该次正文；隐藏、重试与链接失效时不保留旧正文。收藏/评论需要登录的部分仍沿用各自当前权限校验，不为读分享额外开放权限。

统一协调层只持有状态、代际和本次引导结果；不将身份、正文、API 返回值或会话标识写入 localStorage、IndexedDB、Cache Storage、Worker 消息或日志。保留既有创建房间/重开/删除命令收据等非秘密意图键，本需求不新建离线请求队列，也不自动重放不确定是否已提交的动作。

此方案有明确代价：进入后台/断网卸载后，尚未保存到服务器的笔记、表单选择和未提交操作会丢失；已经保存的草稿与幂等意图继续按既有机制恢复。安装/恢复说明需简洁提示先保存编辑，不自动发布、保存、确认技能或替用户提交。不能为了保留未保存表单，把旧私稿复制进浏览器持久缓存。该取舍已随本设计确认，尚未实施，详见[确认记录](../../PRODUCT_DECISIONS.md#pwa-design-approved-2026-10-20)。

## 组件边界与错误处理

- 构建/Worker：建议 `apps/web/pwaBuild.ts`、生成的 `/sw.js`，只定义公开资源清单、缓存策略和更新生命周期；不 import contracts、账号或对局模块。
- 静态服务：建议 `apps/server/frontend.ts`，明确产物类型、缓存头和缺失文件边界；由现有 `main.ts` 调用。无数据库迁移或新业务 API。
- 生命周期：建议 `apps/web/src/SessionBoundary.tsx` 与独立状态协调模块，负责根级隐藏、代际、去重、超时/AbortController 和重试；将 App 的会话初始化与分享首读接入，避免两套初始化竞争。账号切换回调只在已验证的本代际内生效。
- 安装/更新说明：建议独立 `PwaStatus.tsx` 与样式，按需显示安装说明和非模态更新提示。业务页面不显示缓存名、Worker 状态码等实现细节。
- 网络请求：通用 API 与直接 fetch 入口审计 no-store；保留当前 gameId 头、版本/turnId、Cookie、匿名分享方式、限流/Retry-After 与错误信息。超时或离线不得伪造服务端拒绝，更不能清掉仍需人工重试的持久命令意图。

身份恢复、网络重连和 Worker 注册失败应各自有明确状态，不因安装失败锁住在线应用，也不因 API 恢复失败显示“已连接”。无 Worker/不安全 HTTP/开发模式仍使用相同权限恢复保护，普通浏览器不依赖安装才能安全使用。

## 实施后验收要求

以下是预期验证，不是已执行结果。实施计划需要将它们落实为可运行命令与真实断言。

- 构建/真实 Worker：独立生产构建与隔离服务器，校验 Manifest、PNG 像素/类型、路径、Worker/HTML/cache headers、缺失资源不返回 SPA HTML。真实浏览器让 Worker 接管页面后列出 Cache Storage keys 与响应内容，确认仅生成清单条目；加载真实合成身份、私稿、头像、账号、分享及 Socket 后再次对照，查询参数/API错误/POST/跨源均不入缓存。
- 离线：已安装资源的上下文切离线，文档导航得到纯静态断网页；已打开身份/法官/记录/后台/分享即时隐藏，重连引导请求保持失败时旧内容仍不可见，点击重试只恢复权威状态，无自动游戏写入。首次安装缺资源、缓存空间失败不破坏联网路径。
- 前台/迟到：用现有真实玩家夹具验证隐藏后更换账号、撤销法官/管理员、再来一局、分享撤销、VIP失效；延迟旧身份、旧 `/api/session` 与分享响应，再恢复新代际，旧响应不能显示秘密或把新账号退回旧账号。模拟 pageshow/BFCache 与真实浏览器后退/前进可覆盖部分机制，不能冒称 iPhone 系统快照验收。
- 更新：连续提供两个真实构建，验证首次不刷新、waiting提示、两窗口保留旧缓存/旧懒加载、关闭全部后新版本激活及只清本应用旧缓存；任何窗口未保存编辑不得被更新流程自动刷新。
- 手机与回归：320×568、390×844、430×932检查安装说明、断网/重试/更新提示、44px触控、键盘焦点和安全区。运行完整 `npm test`、typecheck、build；开发模式完整既有 E2E，加独立生产 Worker 专项，明确各组统计，不将生产专项并入未实际跑过的完整套件。
- 实机清单：HTTPS iPhone Safari添加到主屏幕、独立启动/关闭重开、真实升级、切账号/退出、实际后台/锁屏恢复、弱网和多窗口。操作系统应用切换器快照、浏览器清理缓存/配额与安装 UI 不由 JS 全面控制，需独立记录观察结果；未验收时保持待真实验收。
