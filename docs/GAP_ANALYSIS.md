# 笔记狼人杀 Gap Analysis｜需求差距分析

核对日期：2026-10-10。范围：当前工作区中的 12 人预女猎白；不考虑九尾／白泽。本报告只核对现状与安排候选任务，不批准新规则，也不修改产品代码。

## 1. 结论与证据边界

当前已经具备完整自动对局、纯手动记录、独立记录版本、账号、基础后台、收藏及 VIP 分享能力。下一轮不应重新开发房间、发牌、完整白天／夜晚、登录或基础收藏。

总表的 163 条及其原始统计（104 已实现、28 未实现、20 需核实、4 待真实验收、其余 7 条边界／未决／未来项）数量一致，但这些统计是交接分类，不是逐条验收结论。以下情况需要修正理解：

- 多数“需核实现状”已存在实现和自动测试；“查看操作”入口已被最新用户决定取消，不能恢复为待开发项。
- 基础收藏已完成，但“通过有效分享链接访问的非参赛普通用户收藏”尚未实现。
- 私人笔记永久删除、公开流程管理审计尚未实现。
- 复盘页面已精简，但底层仍保存并在赛后原始复盘接口返回中间狼票事件，与旧规格“只保存最终有效操作”不完全一致。
- 暂停、账号接管和语音均有实现；不能把历史审计中已经修复的旧会话问题再列成新任务。
- 真实 iPhone、多部实体手机、锁屏／弱网及真实语音仍未验收。自动测试通过不代表这些项目通过。

## 5. 部分实现与新发现的缺口

### GAP-01：有效分享链接的外部读者收藏（ACCOUNT-009）

普通参赛用户已能收藏合法发布的版本；非参赛用户只能读取公共分享投影。`RecordsStore.favorite()` 先调用参与者限定的 `post()`，收藏模型也没有保存分享授权来源；SharedRecordPage 没有收藏入口。本轮内存数据库复现为“链接读取成功，已登录外部读者收藏报 PARTICIPANT_ONLY”。

验收：非参赛普通登录用户从有效链接收藏并跨设备访问；每次打开仍校验原分享授权。到期、撤回、禁用、撤销或重生成旧链接后，收藏不能绕过原链接失效。参赛者原有合法访问能力独立保持；读者不能据 record ID 枚举草稿／历史／他人内容。重生成后的旧收藏是否可迁移必须明确，不能自动绕过旧 token 失效。

### GAP-02：私人笔记永久删除（ADMIN-008）

当前只有删除收藏关系，不能永久删除自己的私人笔记。清空编辑框不等于删除已有记录及相关数据。

验收：仅本人可执行；展示删除范围并二次确认；删除后刷新／重启／旧接口均无法读到该私人内容；不删除其他记录者版本或官方对局事实。已发布版本、撤回版本和关联链接是否属于删除范围须先明确，不能默认为一并删除。

### GAP-03：房主公开管理审计（总表遗漏，区别于 ADMIN-007）

暂停、恢复、授权／收回、未来参数保存和接管警徽有操作权限及确认，但缺少可持久查询的管理审计。控制状态版本号不能替代“谁在何时改了什么”的历史。

验收：服务器记录实际操作者、时间、对局、动作、公开前后值／版本；覆盖原／临时房主及警徽接管，刷新／重启后可查询；无身份、狼票、刀口、私人笔记正文。并发失败不能伪装成功审计；普通玩家不能篡改或越权读运营日志。

### GAP-04：复盘最终事实与原始中间事件未彻底分离（RECAP-001／历史 H-002）

`summarizeReplay()` 的展示已符合精简要求；但 night state 对每次 wolf_vote／priority_wolf_vote 追加事件，存储保存完整状态，`LobbyStore.readReplay()` 将 events 原样放入赛后接口，旧式收藏还保存完整 JSON。因此“界面不显示中间改票”已实现，“不保存中间过程”没有满足旧要求。

验收候选：赛后用户接口／收藏只含最终有效事实；官方纠错和公开管理审计单独保留。如果仍需内部诊断事件，需确认保存期限、数据最小化及访问范围，不直接把现有原始日志当作公开复盘，也不在本轮擅自删历史数据。

### GAP-05：白天自己的身份／剩余技能入口（总表遗漏，历史 S-001）

自己的身份有服务端私密接口；入夜技能按角色显示。但 active RoomLobby 直接渲染 DayPanel，白天主页面没有自己的身份／剩余药剂等入口。测试模式显示全身份不能替代正式玩家功能。

验收候选：如继续保留 S-001，提供只属于本人的按需私密查看，显示准确身份及剩余技能；不提供历史验人结果重查，不破坏普通阶段统一等待或单屏主操作。这个入口与已取消的“查看操作”按钮不同；先确认是否仍保留此产品需求。

### GAP-06：上线备份恢复与诊断仅有部分基础（BETA-010／011）

SQLite 持久化、事务、重启恢复已有；历史报告记录一致性备份和副本迁移哈希核对。本轮没有重新执行生产恢复演练。因此不能说“没有备份”，但定期备份、异机恢复、恢复目标及操作流程尚未形成完整上线能力。`/api/health`、限流、错误码已有，阶段关联的故障日志／告警尚不完整。

验收：备份从一致性 API 生成，存储和访问权限明确；在隔离目录恢复账号、座位、阶段、官方记录、版本及收藏，检查完整性和外键，证明原运行库未受影响。日志可按对局／阶段／错误关联排查，禁止 token、密码、身份／药剂正文及私人笔记内容；数据库不可用有可定位错误。备份频率、恢复目标和告警渠道属于建议配置，确认后实施。

### GAP-07：测试模式入口依赖启动配置，发现性不足（BETA-004）

测试工具并未删除。服务器必须以 `WOLF_TEST_PLAYERS=1 npm run dev` 启动，且不在 production；入口仅限房主的线上发牌、新房间，房主须入座，房间中不能混入另一名真实玩家。首页尚没有直接创建测试房的入口。

本轮发现 localhost:3000 的启动进程未设置该开关。用户明确允许后，仅重启开发服务并开启测试开关，继续使用原 `.data/lobby.db`；未改代码。当前浏览器已显示“补满测试玩家”。当前房间若选实体牌，该按钮仍不可用，这是已定义限制。

验收候选：如需要“直接进入测试模式”，独立开发启动命令与首页可见入口一并设计；能直接建立标记清晰的新测试房，支持自动跟随及身份显示；production 不暴露入口或测试接口，不能混入／代操作真实玩家。属于便捷性补充，不能当成测试引擎重做。
