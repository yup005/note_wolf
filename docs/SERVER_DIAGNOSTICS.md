# 服务端基础故障定位

BETA-011 / GAP-06，2026-10-16本地交付；未部署。仅服务器运维输出，不是游戏审计、复盘或管理员秘密读取入口。

## 排查方式

- `/api/health`正常返回200与`{"status":"ok","storage":"ok"}`；核心账号/会话、房间/座位、准备及昼夜运行表读取失败时返回503、`status: degraded`、`storage: unavailable`和`requestId`。探针不依赖游戏计时、账号读取或普通API限流，并保持来源检查和禁止缓存；不创建会话、不输出路径/表名。它验证有限读取，不证明所有功能、写入、磁盘余量或全库完整性正常。
- API意外5xx返回`requestId`，同时放在`X-Request-ID`响应头；编号由服务器生成，忽略客户端同名头。用编号在服务器标准错误输出中查找对应JSON行。Socket订阅意外失败同样返回编号；预期的无权限、输入/修订冲突仍按原错误合同处理。
- JSON只含服务器时间、`event`、固定`operation`、白名单SQLite类别/通用错误类别与编号。房间接口故障在能读取公开快照时附`gameId`及粗粒度`phase`（准备/夜间/白天/手动/结束）；不能读取时不猜阶段。后台全局计时/清理故障不假装知道是哪一局失败。
- 启动数据库构造失败记录固定类别并拒绝启动，不透传原异常；首次及周期清理、自动计时和Socket断开回调有异常保护。此保护不会修复数据库或自动重放业务请求，自动计时仍按原频率重试，清理仍按原周期。前端构建加载、目录创建、进程级异常及所有第三方输出不由这个局部诊断边界承诺覆盖。
- 同一后台/健康故障操作30秒内合并输出，省略次数记为`suppressed`；恢复时记录`recovered`及原`faultId`。被合并的健康失败继续使用已有日志编号。普通API意外错误逐次记录。日志写入器同步失败被隔离，不改变游戏结果。

## 隐私与运行边界

不记录异常原文/堆栈、SQL、文件路径、请求URL/查询/正文、Cookie、会话/分享凭据、用户名昵称、身份/技能/狼票/刀口或私人笔记；夜间不记录具体角色行动阶段。运行元信息仍应仅由受信任运维访问，应用房主/管理员没有新增日志或数据库下载接口。

本批没有配置外部告警、日志保留/轮转/异机保存、磁盘/写入探测或每局卡住超时检测；这些运维策略仍待配置，BETA-011为部分实现。测试仅临时合成数据库与独立本地服务，不以浏览器模拟认定真实iPhone声音、后台/锁屏、弱网或多手机验收完成。备份和新文件恢复另见[备份说明](DATABASE_BACKUP.md)，执行证据见[验证报告](TEST_REPORT.md)。
