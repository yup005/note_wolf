# 用户登录、收藏与管理后台设计

按用户要求继续开发。现有游客玩法、参赛房主、秘密信息权限和手机优先界面保留。

## 首版边界

默认采用用户名和密码注册 / 登录，不接短信或邮件发送服务。用户已确认采用用户名密码，并确认首版后台范围。后台包括用户查看、禁用 / 恢复、房间公开状态、赛后对局记录。只有一个超级管理员，普通房主不是管理员；后台不能查看进行中的秘密身份、秘密行动或私人笔记。

## 身份与权限

注册时只能创建普通用户。密码使用带独立随机盐的密码派生算法保存，不存明文；登录凭证由服务器产生，放在 HttpOnly Cookie 中。成功登录轮换会话，退出注销会话并恢复新的游客身份。禁用账号使该账号会话失效。

同一账号跨设备使用同一服务器玩家身份，不能在一个房间产生两个座位。中途登录关联当前游客已验证的成员、历史及收藏；同一房间的账号 / 游客已占不同座位时明确拒绝自动关联，不删除已有参赛状态。退出后的游客不能继续读取上一账号秘密。

超级管理员通过本地专用初始化入口创建；注册接口不能申请管理员权限，不能把首个公开注册用户自动提升为管理员。后台入口仅对超级管理员显示，所有后台接口另做服务器权限检查。

## 收藏

首页“我的收藏”及赛后“收藏本局”接到账号身份。同一局重复收藏只有一条，可取消，刷新 / 重启保持。游客已收藏内容在注册 / 登录时关联到账号。收藏只允许有权读取的已结束对局，不提供进行中秘密信息。

当前收藏是已结束自动对局的官方记录。个人发布版本、撤回、版本更新、通知和对外分享仍按需求后续推进，首版不把基本收藏宣称为完整帖子系统。

## 验证

独立会话测试注册 / 登录 / 退出、密码错误、越权管理员请求、被禁用账号、跨设备同一玩家、游客对局与收藏关联、同房间身份冲突，以及手机界面完整流程。旧房间和旧 Cookie 迁移不丢失身份、药剂、死亡、轮次或收藏。

实现：`AuthStore` 使用随机盐与 scrypt 派生密码，账号拥有房间 / 收藏，凭据会话仅保存摘要。`npm run admin:create` 在本地创建唯一超级管理员，随机初始密码写入不跟踪的 `.data/admin-credentials.txt`。受信任服务器环境变量也可初始化首次管理员，但不会重置已有管理员。接口、手机页面及独立客户端测试见 AUTH_ADMIN_TEST_REPORT.md。
