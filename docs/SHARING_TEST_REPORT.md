# VIP 复盘分享测试报告

日期：2026-10-10。基线：详细需求 V1 8.4、9.2 与当前用户确认；白色 / 浅灰圆角卡片、手机优先。没有公网发布、提交或改动真实对局内容。

## 实现与使用

- 登录且有效 VIP 的作者可为本人已结束、主动发布的复盘生成随机只读地址。普通房主不自动获得资格；本轮没有开放分享其他作者帖子的权限。
- 记录编辑器及本人已发布帖子的弹窗提供「对外分享」。地址可复制；剪贴板不可用时明确提示手动长按复制，不假报成功。
- 首页「我的分享」独立列出本人链接。撤回复盘、取消收藏或删除活动房间不丢失管理入口；VIP 到期仍可撤销。管理员不能列出或管理他人链接。
- 访客匿名查看最新主动发布的版本、本局身份及结果，不初始化玩家会话 / 游戏 Socket。保存或提交草稿不改变分享正文；不公开草稿、账号 ID、参局授权名单、原始日志及历史索引。
- VIP 到期 / 取消、禁用账号或撤回正文会暂停访问；恢复后未撤销链接可恢复。主动撤销不会因续期 / 重新发布而复活；重新生成使旧地址立即失效。管理请求含修订号，延迟请求不能覆盖新链接。
- 对外页面每 30 秒及回前台复核权限，失败清除正文。它是赛后阅读页面，允许纵向阅读；对局一屏布局没有改变。不可用地址统一返回 404。

## 数据迁移与运行

已创建 SQLite 一致性备份 `.data/lobby.before-record-sharing-20261010-1791669711999.db`，权限 0600。先在副本迁移，再启动当前开发服务：schema 13 → 14，新增 `record_share_links`，所有原有表逐行哈希一致；完整性 ok，外键问题 0。实际开发库也再次核对一致，新分享行 0，没有替用户生成真实公开链接。既有房间、50 条玩家记录、48 条身份及收藏均保留。

测试环境使用 3100 端口 / 内存或临时文件数据库；当前开发服务运行在 3000，测试玩家已开启。访问方法：

- 电脑：`http://localhost:3000/`
- 同一 Wi-Fi 的手机：`http://10.0.0.91:3000/`，电脑需保持运行；IP 改变时以 `ipconfig getifaddr en0` 查询。
- 分享地址从当前 origin 生成。分享给局域网手机时从 LAN 地址生成；localhost 地址指向接收设备自己的本机，不能直接用于另一部手机。
