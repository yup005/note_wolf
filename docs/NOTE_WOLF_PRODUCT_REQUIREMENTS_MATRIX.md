## 如何使用

- **已实现**：据最新项目交接自述已实现；不是本次重新运行测试的结论。不得列为待开发。
- **需核实现状**：历史提出过具体约束，交接只有上位概述；先检查代码/测试，不能直接视为缺功能。
- **待真实验收**：代码或模拟测试不代表实体 iPhone / 多人公网验收。
- **未实现**：交接明确尚缺或新一轮建议的上线基础设施；以优先级排序。
- **已确定边界 / 暂不开放**：产品行为或约束，不是缺陷。
- **规则待确认 / 未来范围待定**：不能擅自把过往讨论猜测成定稿。
- **依据**：`交接` 是最新交接摘要；`历史` 是旧规则文档或聊天；`建议` 是本次提出的验收/部署规划。

## 优先处理（避免重复开发）

1. 现阶段优先：真实设备、真实多人完整对局、公网封闭 Beta、必要持久化/备份/日志；验证清理在真实设备的体验。
2. 其次：VIP 收藏搜索 / 筛选 / 排序 / 命名等明确未实现产品功能。
3. 然后：点赞 / 评论 / 多级回复 / 通知 / 举报 / 处罚与审计闭环；上线评论时不能缺审核能力。
4. 最后：其他板子、扩展角色、支付。九尾／白泽不纳入本轮规划。
