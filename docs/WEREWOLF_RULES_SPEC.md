## 白天查看本人身份与技能（2026-10-17，S-001 / GAP-05 / Owner5）

依据[既有确认及本批继续范围](PRODUCT_DECISIONS.md#day-self-delivery-2026-10-17)，补齐白天入口；取消的夜间“查看操作”按钮不恢复，现有技能阶段/隐私和夜间播报不改。

- 自动对局白天、游戏未结束时，已入座本人可点“我的身份与技能”，默认收起。显示本人真实身份、自己的已学习身份、当前技能余量及复制技能最早可用夜晚；混血儿只看自己榜样座位、不看阵营，白痴或已复制白痴只看自己的已翻牌状态。没有额外次数技能时明确显示；这是库存查看，实际发动仍遵守死亡原因、阶段及其它原规则，不以有余量推断当前可发动。
- 标准女巫药剂取已完成夜晚的真实剩余、猎人取当前白天消耗；机械/装甲及其它引擎角色取本人当前白天独立技能实例，不用原角色或学习来源的剩余次数替代。接口只选取技能种类、剩余次数/规则内每夜使用及最早可用夜晚，不返回复制来源、技能ID、使用史、上次目标、原始参数、当前刀口、历史验人结果、狼票或其它玩家秘密。
- 新接口仅当前有效会话/本房已入座玩家的本人，严格拒绝指定座位/演员等参数；原房主、临时房主和普通管理员均不能据管理身份代看。当前死亡法官保持另有显式权限，不借此扩大入口。只读允许暂停时本人查看；夜间（包括保留上一天状态）、准备、手动模式和已结束阶段拒绝，赛后仍用既有公开复盘。
- 私密内容不进入公共房间快照、广播、管理记录、语音或本地持久缓存，响应沿用no-store。测试模式选择模拟操作演员不改变此入口的本人身份；不提供模拟角色代看新接口。
- 关闭、切后台、阶段/连接变化、离开房间或账号会话替换即隐藏并丢弃已读内容；回前台须本人重新点开，旧请求迟到不复显。读取出错先清空，明确重试重新读取；响应阶段/座位与页面不符时关闭并同步。弹窗支持键盘关闭/焦点往返与手机内部滚动。

本批不新增手动局未知库存推断、夜间历史回查或任意秘密读取；未定义玩法仍阻断。实际执行与真实iPhone边界见[报告](TEST_REPORT.md)。

## 公开管理记录（2026-10-17，GAP-03 / S-003 / S-004）

依据[继续实施范围](PRODUCT_DECISIONS.md#management-history-delivery-2026-10-17)，扩展现有公开控制，不把秘密补录日志或赛后原始行动史混入此处。

- 仅记录成功的暂停、恢复、授权/收回临时房主、未来投票默认秒数/票型公开程度保存，以及房主替死亡警长实际接管警徽移交。死亡警长本人普通移交不误记为房主接管；失败、旧版本或越权命令不产生成功记录。业务写入与审计同一事务，审计失败则业务一起回滚，不补造历史。
- 服务端保存实际成员、当时公开座位/昵称、时间、动作及固定公开前后值：粗阶段/轮次、控制版本/状态、临时房主座位、未来投票秒数/公开程度、警长及警徽状态。警徽跨夜继续保留。接口只返回公开座位/昵称，不返回成员/账号标识、身份、技能结果、狼票、刀口、私人笔记、私密阶段编号、倒计时或凭据。
- 每次读取要求有效当前会话、本局成员及当前管理资格：原房主（死亡仍可管理）、存活临时房主或显式任命的死亡法官。普通玩家、无本局资格的管理员、房外用户、撤权者和旧会话不可读；不向公共广播附带记录，不提供任意写入/修改/删除接口。
- 按递增记录ID倒序每页20条，严格较早游标保证插入新记录时翻旧页不重复/遗漏。刷新/重启可读取；实时房间清理不删除独立审计，但清理后没有本局读取入口，不新增归档授权或后台审计浏览权，保留期限未由本批代定。
- 管理者在“管理→查看管理记录”或“记录→查看管理记录”按需展开；显示中文动作、操作者/时间和相关前后变化，可刷新/加载更早记录。打开时每30秒及回到前台重读最新20条；读取失败清空已载内容，可重试。失去资格/切换房间会卸载，迟到旧响应不能重新显示。记录编辑页入口适用于赛后及手动记录当前管理者；不开放已清理房间历史访问。

本批仅上述五类动作，不宣称所有公开流程命令均已审计；现有法官秘密补录审计保持独立。RESUME-009更广配置未据此完成；游戏计时、规则、语音和部署不变。实际验证与实机边界见[报告](TEST_REPORT.md)。

## 默认夜间语音、评论滚动与诊断边界（2026-10-16）

依据[Owner直接补充与继续范围](PRODUCT_DECISIONS.md#voice-comments-diagnostics-2026-10-16)，覆盖此前必须手动点开启的设备默认和闭眼间隔旧话术；其余仅夜间播报、前台管理者及单设备租约规则不变。

- 本设备没有显式关闭偏好时默认准备播报，复用既有管理者点击/键盘交互激活本地音频；获得当前夜间权限/连接/租约后才播游戏公开提示。浏览器阻止声音时保留手动开启/重试，不冒称已经出声。手动关闭后刷新和后续夜晚保持关闭，显式开启可恢复偏好；模式切换、隐藏/失联/失权和错误仍停止旧音源，白天和纯手动局不播报。不改浏览器本身的自动播放限制，不承诺无任何用户交互即可有声。
- `eyes_closed`只播“请闭眼。”；不说“等待下一阶段”，5秒闭眼间隔保持，入夜“天黑请闭眼”仍早于首角色。新提示使用预录本地片段，旧公共词库保留兼容，不在播放时生成。
- 已发布记录弹窗的复盘正文、收藏与展开评论共用一处弹窗内部滚动；内容不被压扁，最后评论操作可滚到、正文可回看、关闭可达。权限、版本、评论/回复及发布规则不改。
- 基础故障日志只含安全运行元信息和关联编号，不含秘密或异常原文；粗阶段只取公开层级。健康检查、重复故障合并/恢复及未完成运维策略以[完整说明](SERVER_DIAGNOSTICS.md)为准，不增加房主/管理员日志读取权。BETA-011仍部分实现，不改变判胜、技能与计时策略。

## 后台监督管理范围与期望（2026-10-14）

H-004 / ADMIN-005–007，依据[本批继续授权及Owner第27项](PRODUCT_DECISIONS.md#admin-oversight-delivery-2026-10-14)。本节补齐原后台范围，执行证据单独见报告；不新增玩法或管理员秘密读取权限。

- 后台保留用户/房间/既有评论审核，增加举报汇总、操作日志与公开分享管理。举报按同一评论聚合不同举报账号，显示总人数/待审/已处理数；有任一待审则该组待审，时间筛选按最新举报时间，计数始终是整组，不因筛选只计部分。进入既有评论审核执行逐条处理，不改变删除父正文保留子回复或处罚条件。
- 昵称按字面包含搜索，不把百分号/下划线当通配符；可按日期筛选，各数据集仅提供适用的处理状态/操作类别。日期界面按浏览器本地日转成包含起日、排除次日零点；默认20/最多50条分页，按时间/ID稳定倒序，签名游标绑定数据集及已应用筛选，改筛选后从头读取。
- 导出当前已应用条件的全部匹配管理元信息，最多5000条，超过明确要求缩小范围，不能悄悄截断。CSV含UTF8标记、引号/换行转义和公式/前缀控制字符防护。仅导出昵称、时间、类别、原因、状态、计数及必要标识/公开房号；不含评论正文、已发布复盘正文、未发布笔记、身份/秘密行动、分享token、密码/会话或任意内部JSON。原举报正文证据仅在原有授权审核中查看。
- 实际VIP与账号启用/停用变化记录操作者、目标、时间及安全的前后状态；相同状态不重复记，直接服务层调用也记录且和状态/通知同事务。原社区审核记录统一读入日志，保留真实历史，不伪造过去未记录的VIP操作；新记录保留当时昵称快照，旧记录沿真实存储，不伪造旧昵称。界面用中文说明前后状态/期限及操作结果，不直接展示内部标识或JSON；CSV保留已定义安全元信息。消息30天清理和实时房间清理不删管理审计。
- 管理员只能撤销已结束/已发布记录的现有公开链接，须填原因、明确确认并核对当前链接修订及原管理员账号。当前会话/权限检查在回执之前，链接撤销、审计、作者本人必收通知和请求回执同事务；失败不产生半个操作。同请求原正文重试不重复日志/通知；即使作者已生成新链接，旧回执也不再次撤销新链接，新请求旧修订拒绝。已撤销当前状态不重复发通知/写日志。
- 撤销只让原链接及依赖原授权的收藏/评论/通知来源不可用，不删除记录/私人草稿/其他玩家数据，不把旧收藏名称或日期移到新链接。作者显式重生成不同链接仍按既有规则处理；管理员本次撤销不等于新增永久封禁政策。暂停/撤回链接及实时房间已清理后的归档元信息仍可管理，但不因此读取正文或秘密。
- 读写、游标和导出每次核对当前有效超级管理员；游客/普通用户/失效会话不能借链接、ID或旧回执扩权。后台/账号或权限变化清除已显示管理内容及迟到响应，重新验证后再显示；临时网络失败保留筛选与输入。撤销的丢响应/5xx/408/429沿用原请求/原账号/原修订，不自动生成新操作；旧状态冲突重新读取核对。

工程接口见[设计](superpowers/specs/2026-10-14-admin-oversight-design.md)，[验收场景](WEREWOLF_TEST_CASES.md#后台监督管理验收2026-10-14)与[执行报告](TEST_REPORT.md)分开。未部署；真实iPhone Safari/VoiceOver、锁屏/弱网和真实多手机仍需独立验收。

## 当前：通知中心（2026-10-14）

H-004 / NOTICE-001–005，依据[Owner第26项及本批继续授权](PRODUCT_DECISIONS.md#notification-delivery-2026-10-14)。本节覆盖历史“完整通知/实际清理未接入”状态及旧默认策略建议；不新增游戏规则。

- 登录账号在顶部“通知”查看未读和历史；“通知设置”分别开关复盘更新、评论回复、评论点赞，三项默认关闭，只订阅之后的新事件，不补发旧操作。账号状态/VIP变化和社区处罚消息始终接收，普通管理员不能读取其他人的收件箱；游客无账号通知中心。
- 直接回复向直接父评论作者逐条提醒；评论赞按同一收件人/评论合并计数，新赞恢复未读；自己回复/点赞/发布不自发可选提醒。同一真实源事件跨请求、重试、关闭后重开订阅、删除或重启均不重发。点赞合并保留最初生成时间，不因新赞无限延长保留期。
- 收藏者发布新版后可收到站内更新提醒，单人/版本至多一条。收藏“有更新”独立于开关；新收藏/旧数据迁移以当前版为已看，列表/搜索/评论/通知权限核验不清标记，真正打开当前有效内容后才清除；已登录原分享入口也仅清本人同一原链接收藏，匿名阅读不清除；看旧版不清新版。取消后重新收藏从当前版开始；游客绑定沿原存续收藏关系迁移已看版本，不迁移其他账号收件箱/订阅。
- 每项支持已读、删除，列表支持全部已读、再次确认清空。操作绑定当前账号/消息版本；新界面同时提交原账号前置条件，另一标签页换账号后服务器在回执/写入前拒绝；重新打开后的重试须先验证本人列表。翻页保留首页水位，批量只处理用户刚读取到的修订，新到或新合并通知保留。丢响应/5xx/408/429重试保留原请求编号及完整指令；旧页面冲突读取最新状态，不自动重复提交。
- 通知在最初生成满30天实际清理：启动、收件箱/源操作及每分钟维护检查。仅删除收件箱和旧社区消息展示行，不删除复盘、收藏、评论、处罚状态或审计；幂等/旧事件/迁移标记独立保留，清空或重启不会使旧处罚消息复活。账号“我的账号”保留当前禁评，历史统一进入通知中心。
- 可选消息列表只显示通用标题/数量/时间，不含评论正文、私稿、身份、其他账号ID或分享凭据；处罚原因/账号详情只供本人。点击来源每次重验收件人原授权，回复/赞使用原评论者的入口，不能借回复者链接、重生成的新链接或另一作者版本绕行。旧数据从同作者/同评论原有效创建回执恢复来源；已知原链接即使失效也不替换，无可靠来源则不可用或限原参赛权限。
- 来源内容再次读取；回复/点赞定位实际目标及直接父节点，不受当前分页影响，删除正文隐藏、父节点墓碑保留。撤回、删除、原分享失效、资格/会话撤销均不能借通知扩权；后台/账号变化清除通知和已打开来源、忽略迟到响应。正常发布版本切换仍保留评论输入。通知不进入语音/房间公开快照，不续期实时房间，不发送手机推送。

本批不含通用管理员群发编辑器、全量后台日志/统计或部署；NOTICE-003的账号/处罚消息源不等于完整后台已完成。设计与接口细节见[实施规格](superpowers/specs/2026-10-14-notification-center-design.md)，[验收场景](WEREWOLF_TEST_CASES.md#通知中心验收2026-10-14)与[实际报告](TEST_REPORT.md)分开；真实iPhone/VoiceOver、锁屏/弱网/多手机仍待验收。

## 3. 自动法官：夜间行动

### N-001 夜晚角色顺序与提示 [已确认]

- **12 人预女猎白：狼人 → 女巫 → 预言家 → 猎人查看开枪状态。**
- 夜间角色依板子定义的固定顺序行动，各阶段有独立时限；玩家提前确认可结束其阶段。
- 每一角色结束后，法官播报「该角色请闭眼」，再经过**10 秒独立间隔**，才开始下一角色「请睁眼」。提前确认、超时以及狼队确认均不得省略该间隔。
- 已死亡身份依然保留**外部可观察的虚拟夜间阶段与统一语音时长/提示**，避免通过某个角色不再被叫到推断其死亡或身份；不会执行真实无效技能。
- 房主可指定一台或多台设备播放公共法官语音，其余设备静音；公开语音绝不播报本不应公开的夜间信息。[已确认]
- **[待确认 N-01]** 含守卫等扩展角色的具体夜间顺序，由板子配置；现阶段不能假设守卫在固定位置。

### N-002 普通狼人刀人 [已确认]

1. 夜间开始时，系统从**存活狼人**中随机指定一名本夜最终确认者；仅狼队私人界面显示确认者座位号。
2. 各存活狼人通过手机选择刀口，可以**反复修改**；以结束前最后一次选择为准。
3. 所有存活狼人能实时看到狼队各成员的投票及变化；没投票显示「未选择」。
4. 普通刀口按**得票最多**结算（不是必须过半）；最高得票并列时从并列目标中**随机**选一名。
5. 仅一狼有效投票则按该目标；完全无人有效投票则**空刀**。
6. 指定确认者点击确认后，该狼人阶段可提前结束；到达本夜狼队开始后的 **180 秒**仍未确认，则按已提交的有效投票自动结算。
7. 结束前 **30 秒**，播放不暴露身份的公共剩余时间提醒。
8. 指定确认者**断线后不重新指定**；如其重连仍在 180 秒内可以确认，其余狼人继续正常投票修改。
9. **[待确认 N-02]** 更早曾有「指定确认者超时后随机改选另一狼」的描述；后来确认「断线后不重新指定」和「180 秒自动结算」。是否还存在独立于 180 秒的在线确认者个人超时时点需要核实；开发 V1 不应自行额外引入倒计时重抽确认者。

### N-003 自爆狼下一夜优先指刀 [已确认]

- **所有普通白天自爆**原则上可触发指刀资格，不限第一天；**警上成功自爆吞毒**为例外，不能参加后续夜间指刀。
- 自爆狼仅在**自爆后紧接着的一夜**拥有一次可能的优先指刀权，之后绝不继续实际点刀。
- 资格在**下一夜开始时**判断：必须仍有至少一名存活且与自爆狼夜间相认的**红狼同伴**；若自己是最后一名普通狼人或无符合条件同伴，则无点刀权。
- 有资格者在下一夜狼队阶段，通过**自己手机**秘密选择目标或主动选择「空刀」，可以修改，并可看到各存活狼人实时具体票型。
- 存活狼人同时能实时看到该自爆狼选定/修改的优先刀口，但**不能覆盖**其决定。这些信息只对有权看到的狼队成员开放。
- **自爆狼确认优先刀口或空刀后立即结束狼人阶段，其确认结果覆盖所有普通狼人投票。**
- 自爆狼尚未确认时，普通狼队确认者**不能提前结算**；最多仍等到狼人总上限 **180 秒**。

- 若失去指刀资格，公开流程、语音不得因此显示差异；身份/资格信息不得暴露给非授权玩家。

## 4. 白天流程、竞选与投票

### D-001 第一天天亮 / 警长流程 [已确认]

- **第一天先进行警长竞选，再公布第一晚死讯**，因此存在「前一晚中毒但死亡尚未公布的狼人仍可参与警上流程并自爆吞毒」的特殊窗口。
- 启用警长竞选是默认规则；此板第一天自动发起。
- 玩家手机自主报名「上警 / 不上警」，截止锁定报名名单；**如果所有玩家都上警，警徽直接流失**。
- 警上候选人可以在发言中随时**退水**，之后不得再上警；所有候选人讲话结束后仍设最后退水窗口。
- 最终 0 名候选人：警徽流失；1 名：直接当选；2 名及以上：进入投票。
- 第一轮警长投票：**仅最初选择不上警的玩家**可投；中途退水者不可投。
- 第一轮最高票平票：并列候选人 PK 发言，然后举行第二轮投票；第二轮由**所有存活且不在本轮 PK 候选人中的玩家**投票，包括最初上警或退水的人。
- 第二轮仍平票：警徽永久流失。
- 第一轮竞选发言顺序随机起点；已有警长可决定发言顺序的场合依警长决定。[已确认]
- **候选人演讲与 PK 演讲默认每人 90 秒**。[已确认]
- **[待确认 D-01]** 第一晚已内部判定死亡但尚未公开的玩家，在警上候选/投票/技能资格方面的详细状态；至少**已中毒未公告的狼人允许参与竞选及警上自爆**为明确例外，其他角色不要擅自类推。

### D-002 发言模式 [已确认]

- 默认**自由发言**：系统不对每个玩家单独推进；**房主控制整段发言何时完全结束**，而不是结束某个人的发言。
- 可选**自动顺序发言**：每名符合资格的发言玩家 **90 秒**；超时后播报下一号码；**当前发言玩家与房主均能提前结束该名玩家发言**。
- 自动顺序发言的方向：**有警长则由警长选递增/递减，无警长则递增**；跳过没有发言资格的座位。
- 自由发言模式也给出起始号码提示，但不逐人接管计时。
- 一名夜间死者：以该死者后一位号码作为起点（「死大发言」，越过不可发言者）；两名及以上夜间死者：随机起点；平安夜：随机起点；其他规则按该板配置。[已确认]
- **[待确认 D-02]** 自由发言与顺序发言在警长竞选/警长 PK/放逐 PK 的适用范围，以及房主何时确认「整段发言已完」而进入下步；普通日间发言模式与竞选发言可能需要单独状态。

### D-003 投票 [已确认]

- **每一轮独立投票阶段开始前**，房主可选「手机投票」或「线下投票，房主录入结果」；该轮开始后锁定方式。PK 再投属于新阶段，可重新选择。
- 手机投票默认 **30 秒**，房主可在各轮**开始前**修改该轮时长。
- 具备投票资格的玩家可投有效目标或主动弃票；未提交者在到期时按弃票；所有应投玩家提前提交完毕时可提前结束。
- 票数未结算前不向公众公开票型；房主可在该轮开始前选**结算后公开全部投票人→目标及弃票者**，或**只公开候选人汇总得票及结果**。
- 警长在白天**放逐投票**中拥有 **1.5 票权重**，普通玩家 1 票。
- 白天放逐第一轮最高平票→平票者 PK 发言，其他符合资格者重投；第二轮仍平票→**本日无人放逐，进入下一夜**。
- **[待确认 D-03]** 白天放逐 PK 第二轮若警长也在 PK 中，警长票权及投票资格如何处理；其他边界（弃票、全零票、离线、没有可投目标）待验收用例明确。

### D-004 警徽 [已确认]

- 警长死亡时，可**将警徽移交给一名存活玩家**或**撕掉警徽**（本局永久失去）。
- 警徽移交属于公开操作，**没有固定截止时限**；必要时房主可以依公开流程接管规则处理，须二次确认及审计。
- 原房主可以死后继续管理公开流程，亦可主动授权一位存活玩家为临时房主；管理权限不改变角色或身份。

## 5. 自爆、吞毒与双爆吞警徽

### X-001 普通自爆 [已确认]

- 狼人须通过**二次确认**自爆。
- **仅限白天投票开始前**的允许阶段；投票开始后不再允许自爆。
- 自爆成功立即打断当天正常白天流程；通常**没有遗言，进入下一夜**（如胜负已定则立即结束）。
- 普通自爆是否有下一夜指刀资格，依 N-003 判断。
- **[待确认 X-01]** 「投票开始后不能自爆」是仅投票进行期间，还是该日一旦启动过任何投票阶段就彻底锁死；V1 不得自行把所有中间间隙都解释成可自爆。

### X-002 警上自爆吞毒 [已确认]

同时满足以下条件才算**吞毒成功**：

1. 自爆者为**前一夜已经遭女巫有效毒杀、但死讯尚未公布的狼人**。
2. 自爆发生于**尚在进行的警长竞选阶段（警上）**；首日或竞选顺延后次日等均可。
3. 狼人主动完成自爆二次确认。

结算：

- **女巫毒药已经使用，不返还**；自爆者只计一次死亡，避免再次毒杀造成重复死亡事件。
- **系统不公布「吞毒成功」**，不能在公共语音/界面泄露女巫是否用药。
- **成功吞毒的自爆狼不能参加随后一夜的优先指刀**，与普通自爆不同。
- **只有第一天警上成功吞毒的自爆狼拥有 90 秒遗言**；第二天及之后成功吞毒没有遗言。
- 其他夜间死亡按真实结果公布，例如：「3 号、7 号死亡，**死亡顺序不分先后**」，继续符合条件的死亡技能与遗言流程。
- **[待确认 X-02]** 第一日警上自爆时，死亡结果公告、自爆者首日遗言、竞选中断与第二夜开始之间的**精确事件顺序**；不要把一般「立即入夜」直接套到吞毒特殊分支。
- **[待确认 X-03]** 如果被毒狼在警上选择不自爆，死亡何时生效、竞选已提交的投票等是否有效；目前仅明确其可进入未公布死讯的竞选窗口。

### X-003 双爆吞警徽 [已确认]

- **尚未选出警长**的竞选过程中，第一名狼人自爆→警长竞选**顺延至第二天**，不立即吞掉警徽。
- 第二名狼人再次自爆，且**此时仍未选出警长**→**警徽永久流失**。
- 若第二次自爆发生在警长已经选出之后，不触发「双爆吞警徽」，不会凭自爆抹去已有警徽。
- 该规则与 X-002 吞毒机制分别判定，可以在满足各自条件时共存；结算顺序仍需由测试验证。

## 6. 死亡、遗言、猎人及胜负判定

### R-001 夜间死亡与白天死亡 [已确认]

- 夜间：先把本夜狼刀、毒药、救药、守护等技能统一结算成最终死亡集合，**先判断游戏胜负**；若已分出胜负，**立即结束**，不再进行猎人开枪或遗言。
- 未分出胜负：可进入公布死讯、统一的死亡技能询问及有资格者的遗言；多个夜间死者**随机排序处理**，公开公告均为「死亡顺序不分先后」。
- 白天：**每出现一名新死者，立即检查胜负**；如已决胜负，停止其他尚未进行的技能、遗言、警徽移交。
- 任何时点胜负确定，立刻正式结束，不再走未开始的后续环节。[已确认]
- **[待确认 R-01]** 夜间死讯尚未公布前发生的警上自爆吞毒，和「夜间先结算死亡并判胜」如何排列：需要把“夜间内部结算”、第一日警上特殊窗口、公开公告、胜负触发明确建成事件状态，不能让已中毒待公告狼错误提前消失。

### R-002 死亡技能统一问询 [已确认]

- **所有死亡玩家**都使用同一公共问询：「X 号玩家是否发动技能？」；统一默认 **10 秒**。
- 有有效死亡技能者可在 10 秒内触发；成功触发转入实际技能流程。
- 没有成功触发则**等满 10 秒**后统一播报「X 号玩家没有发动技能」。
- 不得通过技能按钮可见性、语音、问询缺失、是否被毒等暴露隐藏角色/死因。
- 毒杀导致无法开枪的猎人即使私下尝试，系统只能提示其本人失去开枪资格；公共语音按「没有发动技能」处理。

### R-003 猎人 [已确认]

- **狼刀致死**或**白天投票放逐**：若未先判定游戏结束，有资格选择是否开枪。
- **被女巫有效毒杀**不能开枪；若同夜既被狼刀又被有效毒杀，**毒杀优先，不能开枪**。
- 被狼刀且同守同救「奶穿」死亡，**仍可开枪**，但若同夜也被有效毒杀则不能。
- 猎人真正开枪时，**线下口头报目标，由房主在系统中录入**，而非猎人在个人手机上自动指选。
- 猎人击杀引发的新死亡**立即插入**当前死亡处理队列（深度优先），处理完新增死者，再返回原队列；任何人同一次死亡事件的技能、遗言只能处理一次。
- 猎人若为最后一名神职，其死亡已经让狼队胜利→**不能开枪，游戏立即结束**。
- **[待确认 R-02]** 由猎人射杀的新死者在夜间链式死亡时，是否立即再检查胜负（白天链式死亡已明确逐死者检查）；应和 R-001 的夜间批量判胜规则保持一致。

### R-004 遗言 [已确认]

- 有遗言时，每人 **90 秒**，**发言玩家或房主**可以提前结束；超时自动进入后续流程。
- **第一晚死亡**：有遗言，若多人死亡则各自独立 90 秒。
- **第二晚及之后夜间死亡**：无遗言。
- **白天投票放逐者**：有遗言，除非胜负已定直接结束。
- 猎人第一晚被刀并开枪带走的人：有遗言；第二晚及之后猎人夜间死亡并开枪带走的人：无遗言；白天放逐猎人开枪带走的人：有遗言。
- **普通自爆狼人**：无遗言；**第一天警上成功吞毒**：有遗言；第二天及之后警上成功吞毒：无遗言。
- 死亡技能与遗言按随机原队列处理；技能新增死者优先插队，其后返回当前死者未完成的遗言。

### R-005 胜负优先级 [已确认]

- 所有板子按**板子定义**配置胜利条件，不能在整个系统写死屠边。
- 12 人预女猎白的已确认**特殊优先级**：
  1. **最后一神是猎人**，猎人死亡使狼人获胜时，不允许再开枪。
  2. **最后一神女巫**当晚被狼刀，且其毒药同晚毒死**最后一狼**，判**狼人胜利**。
  3. 屠边局**最后一民与最后一狼同夜死亡**，判**狼人胜利**。
- 夜间先结算死亡集合后判胜，避免夜死者随机处理顺序影响胜负；白天逐死者判胜。
- 胜负一旦确定，立刻宣布获胜阵营、停止遗言/警徽移交/未触发技能；赛后同步公开**所有真实身份**。
- **[待确认 R-03]** 屠城、多阵营以及其余**双方同时达成胜利条件**的优先级，应该由每张板子的显式优先级表规定，不要一律套用狼人优先。

## 7. 网络、隐私、语音及房主管理

### S-001 夜间信息防泄露 [已确认]

- 夜间所有玩家手机默认同一深色**隐私遮罩**，始终显示一致的「查看操作」入口；仅该阶段有合法操作资格者点击后可看到私人技能页。
- 玩家在有效阶段可随时隐藏并重新展开尚未确认的技能界面；隐藏不等于放弃，不重置倒计时。
- 手机锁屏、页面切后台时立刻恢复遮罩；回前台先按服务器时间同步状态，仍需玩家主动点击「查看操作」，保留未确认选择但已过期的不再可提交。
- 白天每名玩家可看自己的身份和剩余技能，不显示历史查验结果或行动记录。
- 游戏期间默认尝试使用浏览器 Screen Wake Lock 保持常亮，玩家可自行关闭；游戏结束释放，系统或浏览器限制导致失败时正常恢复状态。

### S-002 就绪与断线 [已确认]

- 每晚开始前的手机就绪检查由房主**开局前配置**，**默认全员强制确认**；已死亡玩家也参与。另一模式为全员统一提醒即可。
- 强制模式若有人未确认，房主可看到未就绪座位，线下提醒后**二次确认强制开始**；不因此查看角色身份。
- 手机断线时**不暂停**游戏计时；回连后自动同步当前状态。
- 每位玩家每局仅有 **一次 15 秒断线重连宽限**，根据服务器断线/重连记录**自动触发**，不是由房主批准。
- 非狼人秘密角色到普通阶段终点时若符合条件：主机公共播报「**系统连接异常，正在重新连接，请稍候**」，额外最多 15 秒；玩家仍离线则等待满额并跳过技能，**宽限机会消耗**。
- 一旦进入下一个角色阶段，不能返回补交此前已结束阶段的技能；房主无权提前截断这 15 秒或代替夜间秘密技能。
- **狼人阶段总时长严格不得超过 180 秒，任何断线宽限都不能突破上限**。单狼断线不应阻碍其他狼投票，负责最终确认的普通狼断线也不改选，届时按票自动结算。
- **[风险 S-01]** 仅在特定秘密角色阶段触发「系统重连中」播报，虽然不报座位，也可能让现场玩家依据所处夜间阶段推断该角色断线。用户已确定采用该提示方案；正式实现需进行隐私泄露评估，必要时再确认不泄露阶段的具体策略。

### S-003 暂停与恢复 [已确认]

- 原房主、获得授权的临时房主均能暂停/恢复；**暂停和恢复都需要二次确认**（以最新确认覆盖曾经的「暂停立即生效」）。
- 暂停冻结所有计时、技能提交、投票、自动阶段切换；操作与未提交选择保存。
- 暂停次数和时长**均无限制**；不会自动恢复。
- 恢复经二次确认后，全体统一经历**5 秒准备倒计时**（不消耗原阶段倒计时），之后继续原状态。
- 暂停期间可批量修改**未来阶段、原本可配置的非规则性参数**（例如发言/投票时长、语音设备）；保存时展示变更清单并二次确认；不能修改身份、角色组合、胜负条件、技能规则、固定时间或已经开始的当前阶段计时。
- 变更不主动通知全体玩家，直到相应阶段才显示新设置；所有管理行为记审计日志。

### S-004 房主管理与设备恢复 [已确认]

- 房主可介入**公开**且需要人工操作的停滞环节（例如警徽移交、线下投票录入）；**二次确认并审计**。不得介入夜间秘密技能。
- 原房主死亡后仍能继续处理公开管理，亦可主动授予存活玩家临时房主权限；管理权限不会改变游戏身份。
- 原房主失联且没有临时房主：自动流程继续，需房主操作的公开流程等待原房主回来，不投票产生替代管理者。
- 未登录的游客房主可以创建房间；创建时仅提醒**一次**「未绑定账号无法跨设备恢复管理权限」，仍可游客继续。
- **游客房主只有在设备丢失前先绑定登录账号，才能跨设备恢复房主权限**；无单独的房主恢复码方案。[已确认]
- 玩家（非房主管理权）可在游戏中途登录自动绑定本次及设备可证明参与身份的历史对局。
- 同一账号同一局只绑定一个座位，跨设备登录后新设备接管、旧设备立即失去操作及实时秘密信息权限。
- 游客玩家换设备：通过房间号 + 专属座位恢复码；丢码可由房主线下核实身份后批准接管，不展示隐藏身份。每次恢复后旧码失效、新设备获得新码，旧设备失效。

## 8. 手动记录、官方判胜与赛后复盘

### H-001 手动记录权与版本 [已确认]

- 房主和参与该局的 VIP **分别独立编辑各自的记录**，**不是共同编辑同一份文档**。
- 可手记死讯、警徽、投票/票型、放逐及推理。**游戏进行中不会自动向所有玩家公开手动票型**。
- 各自个人笔记默认私人，游戏结束后记录者可选择发布自己的**复盘版本**；多人的版本并存，可单独收藏。未发布的个人笔记只属于本人。
- 系统不知道的线下投票、技能或死因，须标记「未记录」，**禁止捏造**。
- 纯手动对局与自动对局同样可长期保存历史、收藏以及由 VIP 对外分享。
- 玩家身份来源始终是线上自动发牌或实体牌私密录入，服务器可以在手动模式依据身份 + **有效死亡记录**判胜。
- 房主记录优先作为**官方死讯与官方胜负**的基础；VIP 个人记录有冲突时不覆盖其独立版本。[已确认]
- VIP 可以发起结束，进入「**待最终确认**」状态；房主可**拒绝**并恢复游戏或修订记录。系统依据官方死讯和板子胜利条件决定获胜阵营；不让记录人凭主观直接定胜负。
- 正式结束后房主仍可修正官方死讯并触发重新判胜；保留每次**修订历史**和「已修订」标记。[已确认]
- **[待确认 H-01]** 没有房主批准、房主长时间失联时 VIP 的结束申请如何处理；已有规则仅明确房主可拒绝、最终官方死讯以房主记录为准。
- **[待确认 H-02]** 线下手动发生猎人射杀、警上吞毒等事件时，需要记录哪些死因/技能来源来保证自动胜负判定与白痴双边状态准确。

### H-002 赛后复盘 [已确认]

- 游戏正式结束后向所有玩家自动公开完整身份与胜负；所有玩家可查看**最后有效的**夜间行动、技能目标、投票、自爆、死亡及胜负结算。
- **不保存改刀、改票等中途修改的完整过程**；只保留最终有效操作。**赛后房主纠错修订历史**及**房主接管/后台审计日志**单独保留，不受此限制。
- 复盘长期保存，每局拥有独立标识。
- 记录者撤回**自己的已发布个人复盘版本**后，收藏关系保留但他人暂时不能查看；重新发布后恢复访问，不影响官方结果。
- 已发布个人版本允许在**独立草稿**中修改，只有主动「发布新版本」才向收藏者同步；旧发布版本及修订历史可查看。
- 房主对官方死讯的赛后修订自动反映在有效分享链接展示的**官方部分**，并显示修订历史；不擅自覆盖 VIP 私人版本。

### H-003 分享、收藏与点赞 [已确认]

- 同一局可有多个 VIP 分别生成对外复盘链接；**各 VIP 只管理自己生成的链接**；超级管理员可在后台管理全部链接。
- VIP 必须登录；开通、到期时间、取消均由超级管理员后台设置。支持永久或自定义限时 VIP。
- **VIP 到期**：其已发布的对外分享链接自动暂停，续期后恢复；本人**仍可撤销旧链接**，但必须恢复有效 VIP 才能创建/重新生成。已主动撤销的链接不会自动复活。
- 原房主**不因是房主就有 VIP 对外分享权益**；可以免费向**本局参与者**提供复盘；对外分享仍需 VIP。[已确认]
- 用户通过有效链接查看对局；任意已登录普通用户可以收藏有权限查看的对局；VIP 收藏管理提供搜索、板子筛选、日期排序及自定义名称，普通用户有基础收藏/取消收藏、时间倒序及链接状态。[已确认]
- 有效分享链接被撤销或因 VIP 到期暂停后，收藏入口保留但不能绕过链接权限重新打开；恢复链接权限后可继续查看。
- 同一局所有复盘版本共用**同一个评论区**。
- **对局点赞**：一个登录账号对**同一局每天最多一次**，不可取消，跨复盘版本共享限制；每日额度重置、累计点赞保留。
- **评论/回复点赞**：一个登录账号对**每条评论或回复终身只能一次**，不可取消；独立于对局点赞。
- **[待确认 H-03]** 「房主想收藏分享对局也需要 VIP，除非分享给参与玩家」这一表述与「普通用户可收藏有权访问的对局」存在语义交叉。当前可确定的是**对外生成分享链接必须 VIP**；房主收藏自己的未发布官方版本是否另需 VIP，实施前应确认。

#### H-003 收藏管理实施说明（2026-10-11，v1；本地实现，未部署）

- 有效 VIP 可组合名称/默认标题/房间号/合法可见已发布内容搜索、板子/作者/收藏日期筛选和收藏日期正序/倒序。日期输入按浏览器本地日转换为绝对时间边界；并列时间使用稳定顺序。草稿及已撤回正文不参与搜索，不返回正文命中摘要；打开继续校验原权限。
- 收藏板子与作者使用公开归档元数据，清理实时房间后仍保留；可回填的旧板子读取原配置，缺失时标为未知，不按身份推断。普通账号默认时间倒序，原查看/取消权限不变。

#### H-003 外部分享读者收藏（2026-10-11，v2；ACCOUNT-009 / GAP-01；本地实现，未部署）

依据原“任意已登录普通用户可以收藏有权限查看的对局”确认及2026-10-11本次继续开发指令。用户明确选择：**重新生成分享链接后，保留旧收藏但显示失效；读者取得新链接后自行重新收藏**。这解决GAP-01迁移待决项，不更改H-03或参赛者独立权限。

- 匿名分享继续只读且不创建Cookie；主动收藏时可登录/注册，普通登录账号无需VIP。服务端先验证当前链接，再保存本人收藏及原授权来源；重复收藏同一链接幂等。
- 首页列表、正文搜索及每次打开沿用原分享投影与权限检查；作者VIP到期、禁用、撤回、撤销或重生成旧链接均不能借收藏读取正文/草稿/历史版本。列表保留已收藏公开元数据及个人名称，失效内容不参与正文搜索；同一原链接续期/重发布恢复后可再次查看，主动撤销旧链接不会复活。
- 新链接手动收藏形成独立关系，不自动转移旧链接收藏、名称或日期。分享收藏不会转换为参与者收藏；参赛者通过原权限查看其复盘的能力独立保持。
- 收藏ID与分享凭据分开，收藏关系中的原链接凭据仅存服务端，不在收藏列表回传或进入公开房间。有效VIP可使用已有搜索/筛选/排序/本人命名。任何分享收藏都按既有G-003保护实时房间，取消最后保护后恢复原24h清理；独立发布档案及元数据不随实时清理删除。

自动验证及真机边界见 [当前验证](TEST_REPORT.md)。收藏状态请求失败提供独立重试，前台恢复/定期重读时若授权失效清除已显示正文。

#### H-004 个人记录永久删除（2026-10-14；ADMIN-008）

来源：[Owner第一轮第2项](PRODUCT_DECISIONS.md#owner-decisions-2026-10-12)，沿用用户“继续”和不重复询问的开发授权。本人可二次确认删除本局自己的私人草稿、个人推理和全部发布版本，并撤销关联分享；**已被采纳的官方事实、其他作者记录、对局级评论保留**。区别于G-003实时房间清理和可恢复的发布撤回。

- 首页“我的记录”及局内“记录→永久删除我的记录”使用同一确认；实时房间清理/VIP到期仍可删除。游客限持有的本人会话，登录账号跨设备沿用账号所有权；不增游客凭据恢复或管理员代删权限。
- 再次确认说明不可恢复及保留范围，取消不写入。服务端核对草稿修订、发布版本及撤回状态；旧确认拒绝。丢响应沿用原请求重试，不能重复删除/新建或删除另一份；失效会话不能借旧回执授权。
- 同一事务清除私人草稿、全部发布正文/版本来源和分享凭据，只保留不含正文的最小删除标记/回执及收藏档案标记，已发布作者的原公开归属用于保持收藏标题/筛选。参与者收藏可显示“已永久删除”，外部收藏保留条目/名称/日期、清除原凭据并永久不可读；均不以正文搜索命中。新记录不会重新授权旧ID/链接/收藏。
- 官方采纳仅保留事实，私人推理留在本人草稿/主动发布中；删除房主个人记录前，先把当前官方事实独立归档（兼容仅有旧发布副本的归档），不把未采纳草稿作为官方事实；再清空旧官方历史/实时文档/独立快照中曾复制的私人推理，保留死亡、警徽、票型、胜负、修订和操作者。不得删除其他作者正文。
- 未采纳结束申请按服务端来源记录ID取消，不按昵称猜作者。历史申请缺来源时仅可靠唯一归属匹配；无法确定则拒绝删除，提示先由房主处理该申请，避免误删别人申请或残留源文档。
- 读取不自动重建已删草稿；有资格者主动点“新建记录”，创建新ID/更高修订，房主沿用官方事实且推理为空。旧编辑/发布/官方提交不能修改新记录；绑定账号迁移删除标记/回执；若与账号已有独立活跃记录/已删标记冲突，原子拒绝合并，不丢双方记录。会话变化重新装载私密编辑/确认，重启/实时清理不复活已删内容。
- 此为当前应用数据的逻辑清除，不宣称改写外部历史备份、已被读者复制的内容或SQLite释放页的物理字节。发布读者页面在前台恢复/定期重读时复核权限，确认失效清除正文及相关入口。

实施/执行证据见[交接](PROJECT_STATUS_FOR_CHATGPT.md)和[报告](TEST_REPORT.md)，工程默认见[设计](superpowers/specs/2026-10-14-personal-record-deletion-design.md)；不部署、不代替真实iPhone验收。

## 11. 推荐实现边界（仅建议，尚非用户确认的技术架构）

- 用 `game_id + seat_id` 唯一标识对局中的玩家座位，`room_code` 仅用于寻找有效房间；账号/设备凭证与座位授权另行管理。
- 让服务器独占合法动作校验、时间、胜负及技能结算；手机只能提交针对自己角色有权的操作。
- 区分**内部隐藏死亡结算**、**公开死讯公告**、**预公告警上窗口**、**日间逐死者胜负检查**，而不是单一 `alive` 状态硬编码所有玩法。
- 胜负判定使用 **board-specific priority policy**；为 14 人双边角色保留多个胜利条件参与状态，而不是一律 `is_alive`。
- **对局事实**、**官方赛后修订**、**私人笔记**、**个人已发布复盘**、**运营审计**分开保存，权限和是否公开各自检查。
- 公共语音和所有客户端计时依服务端统一阶段状态，保证闭眼缓冲、虚拟夜间流程及暂停/恢复一致性。
- 服务器端严格防止未授权读取秘密数据；如要求「即使数据库运营人员也不能看到私人笔记明文」，需进一步选择加密/密钥方案，而不只是隐藏后台按钮。
