# 狼人杀 Web App 需求验收表

审查日期：2026-10-09（America/Los_Angeles）。

验收基线：用户本次提供的《狼人杀 App — 详细需求汇总 V1》。本表使用该清单的 P0–P3 优先级，替代前次审查中的优先级划分。

审查方式：内置浏览器实际访问 http://localhost:3000/；建立测试房间 4921，房主昵称“审查测试房主”，选择 1 号座位；测试 OTP 输入、粘贴、复制、刷新恢复和手机布局。随后再次检查当前大厅。未修改代码、未操作真实对局。

## 判定边界

- 已实现：限本次可观察且实际验证的行为，不代表所有异常情况通过。
- 部分实现：要求中的部分行为通过，其余未开放或无法验证。
- 未开放：当前页面没有入口，且大厅明确提示“发牌与对局功能将在后续开放”；不等于已查明后端没有实现。
- 无法验证：浏览器条件、未开放流程或时间条件不足。
- 存在冲突：有直接观察证据与已确认要求相反。本次未证实核心规则冲突。

## 必须保留的待确认事项

1. 首夜内部胜负检查相对警长竞选、吞毒窗口、公开死讯的精确时点。
2. 警上吞毒之后，竞选中断／顺延、其他死讯、死亡技能、遗言与终局检查的完整顺序。
3. 自动转手动后是否允许返回自动；如允许，如何验证期间的技能、药剂、死亡、警徽、阶段状态。

这三项不能由实现者默认补全。已确认的局部规则照常保留。

## 建议下一轮开发与验收

1. 完成 P0 房间基础验收：独立客户端并发入座、同座竞争、前导零、房间唯一性、重连／接管权限；验证支持范围内的真实 iPhone。
2. 补齐发牌方式与游戏模式的独立配置；完成线上私密身份确认、线下输入及统一数量错误提示。明确开局条件和准备流程。
3. 在规则引擎前确认上述三项问题；直接将已确认的 12 人白痴、死亡询问、指刀、吞毒和胜负优先级纳入状态设计及自动测试。
4. 完成一局端到端自动法官：浏览器动作、服务端状态、计时、公开播报、死亡和结束记录一致，并验证非授权客户端拿不到秘密。
5. 增加暂停／重连与手动记录，再做 P2 多版本复盘，最后做 P3 账号和社交。

不建议在普通流程完成后才临时追加吞毒、指刀和死亡优先级的架构；这些规则影响内部状态，应先纳入设计，再分阶段开放页面。

## 本次结论

视觉总体符合，基础房间和座位已有可用操作。P0 多人独立客户端验收尚缺证据，发牌及后续游戏流程未开放，因此第一阶段仍未完成。未证实核心规则冲突，也未证实规则引擎、服务端秘密隔离或完整对局已实现。
