可以。我把我们之前讨论的内容重新整理成一份**更详细的狼人杀 App 需求清单**，包括很多容易在开发过程中遗漏的小规则。

这份可以直接用来检查 Codex 目前开发的 `localhost:3000` 是否符合我们的设计。

# 狼人杀 App — 详细需求汇总 V1

## 一、产品定位与整体设计

我们要做的不是单纯的狼人杀自动法官，而是一个面向线下面杀玩家的工具，结合三个核心功能：

| 核心模块 | 功能 |
|---|---|
| Automatic Judge | 自动主持夜间技能、警长竞选、发言、投票、死亡结算 |
| Game Recorder | 房主和 VIP 独立记录死讯、票型、警徽变化、个人推理 |
| Game Replay | 赛后复盘、多版本记录、收藏、分享、评论 |

**视觉设计已经基本确定：**

- 白色、浅灰色背景，简洁工具型风格。
- 模块化、卡片化布局，圆角卡片和细边框。
- 深灰色主按钮，少量蓝色用于交互状态。
- Mobile-first，重点优化 iPhone 浏览器。
- 不使用传统狼人杀的暗黑、奇幻、复杂动画风格。
- 游戏中尽量减少操作步骤。

## 二、房间系统

### 2.1 创建和加入房间

| 功能 | 具体要求 |
|---|---|
| 房间号 | 系统自动生成四位数字 |
| 加入方式 | 玩家输入房间号，不使用二维码 |
| 输入界面 | 四个独立视觉格子，类似手机验证码 |
| 输入体验 | 自动跳格、退格、支持粘贴 |
| 加入操作 | 输入四位后自动查找房间 |
| 前导零 | 支持 `0001`、`0027` 等 |
| 房间号唯一性 | 同时有效的房间不能重复 |
| 房间清理 | 普通闲置房间超过 24 小时自动清理 |
| 历史记录 | 清理房间不删除已保存的历史对局 |

房主与普通玩家都不需要注册就可以开始玩。

游客房主创建房间时，系统提醒一次绑定账号的风险，但允许继续游客创建。

### 2.2 座位系统

玩家加入后自行选择座位。

系统需要维护每个座位的玩家、身份、存活状态和相关权限。

同一账号在一局游戏中只能绑定一个座位。

已经登录的玩家更换设备时，新设备自动接管，旧设备立即失去原座位的操作权限和实时秘密信息访问权限。

游客更换设备可以使用专属恢复码；恢复码丢失时由房主线下核实后批准。每次成功恢复后，旧恢复码失效并生成新码。

### 2.3 两种发牌方式

这是我们后来特别修改过的需求。

**线上自动发牌**

系统根据板子随机分配身份，每个人在自己手机上查看角色。

**线下实体发牌**

玩家先实际抽取实体角色牌，再进入对应座位，通过手机秘密选择自己的角色。

系统核对所有玩家输入的角色数量是否与板子一致。

如果不一致，向所有人统一提示检查角色，不能指出哪个玩家输入错误，也不能泄露具体身份。

### 2.4 游戏模式与发牌方式独立

因此一共有四种组合：

| 发牌方式 | 自动法官 | 纯手动记录 |
|---|---|---|
| 线上自动发牌 | 支持 | 支持 |
| 线下实体发牌 | 支持 | 支持 |

自动法官和手动记录还可以同时进行。房主也可以中途切换到纯手动记录模式。

## 三、12 人预女猎白板子

这是我们确定要优先开发和测试的第一个板子。

### 3.1 角色组成

| 角色 | 数量 |
|---|---:|
| 普通狼人 | 4 |
| 预言家 | 1 |
| 女巫 | 1 |
| 猎人 | 1 |
| 白痴 | 1 |
| 平民 | 4 |
| **总计** | **12** |

胜利条件采用**屠边**：

狼人杀光所有平民或所有神职获胜；所有狼人死亡则好人获胜，但要遵守后面已经确认的特殊胜负优先级。

### 3.2 白痴规则

你特别纠正过这一点。

**12 人预女猎白：**

白痴被白天投票放逐时，公开翻牌，**正常死亡，不免死**。

夜间被刀或被毒死，不主动公开白痴身份。

**14 人白痴双边：**

这是一套不同规则。白痴翻牌后神职身份计死亡、平民身份仍计存活，但不能投票和发言。

这两种白痴机制不能混用。

### 3.3 夜间行动顺序

你已经明确指定：

**狼人 → 女巫 → 预言家 → 猎人查看开枪状态**

| 阶段 | 已确定时间 | 行动 |
|---|---:|---|
| 狼人 | 最长 180 秒 | 投票决定刀口 |
| 女巫 | 60 秒 | 解药或毒药 |
| 预言家 | 30 秒 | 查验好人或狼人 |
| 猎人 | 30 秒 | 查看能否开枪，点击已查看 |
| 闭眼间隔 | 10 秒 | 进入下一角色阶段前等待 |

猎人夜间不真正开枪，只查看当前开枪状态。

即使某个角色已经死亡，系统也要维持相应的虚拟夜间流程及公开语音，避免通过缺少播报泄露死亡身份。

### 3.4 预言家

预言家每晚可以查验一名存活玩家。

系统只返回：

- 好人
- 狼人

不会直接展示具体角色。

确认查验后，结果在预言家的私人界面显示，并提供查看结果的时间。

白天不提供历史查验记录，预言家需要自行记忆。

### 3.5 女巫

已经确定的规则包括：

| 情况 | 规则 |
|---|---|
| 解药 | 全局只能使用一次 |
| 毒药 | 全局只能使用一次 |
| 同夜双药 | 禁止 |
| 自救 | 任何夜晚都不能自救 |
| 救人目标 | 解药只能救当晚狼刀目标 |
| 使用解药后 | 后续夜晚不再显示狼刀目标 |
| 自己当晚被刀 | 仍然可以使用毒药 |
| 操作超时 | 没有确认就不使用药剂 |

后续其他板子存在守卫时，还要支持**同守同救奶穿**。

同一晚守卫保护且女巫解救同一个狼刀目标，目标反而死亡，解药仍然消耗。

### 3.6 猎人

- 被狼人击杀，可以开枪。
- 白天被投票放逐，可以开枪。
- 被女巫毒杀，不能开枪。
- 同时被狼刀和有效毒杀，毒杀优先，不能开枪。
- 同守同救奶穿导致死亡，可以开枪；但同时受到有效毒杀仍然不能开枪。
- 猎人可以自行选择不开枪。
- 实际开枪时，猎人线下口头指定目标，由房主录入。

猎人是最后一神时，如果其死亡已经导致狼人获胜，**立即结束游戏，不能再开枪**。

## 四、狼人夜间行动与特殊自爆

这一块是我们讨论最多、最不能遗漏的部分。

### 4.1 普通狼人刀人

| 功能 | 规则 |
|---|---|
| 投票 | 每名存活狼人分别投票 |
| 改票 | 可以反复修改，以阶段结束前最后一次为准 |
| 狼队信息 | 存活狼人实时看到彼此票型和改票 |
| 票数计算 | 最高票目标成为刀口 |
| 平票 | 最高票目标之间随机选择 |
| 只有一狼投票 | 使用该狼刀口 |
| 无人投票 | 空刀 |
| 最终确认 | 随机指定一名存活狼人 |
| 确认后 | 提前结束狼人阶段 |
| 确认者断线 | 不重新指定 |
| 180 秒超时 | 根据已有投票自动结算 |
| 最后 30 秒 | 公共语音提醒剩余时间 |

随机指定的确认者座位号，只在狼人私人界面显示。

### 4.2 普通狼人自爆

狼人只能在**白天投票开始前**自爆。

自爆需要二次确认，成功后立即中断当前白天流程。

普通自爆没有遗言。

### 4.3 自爆狼入夜指刀

这是你专门制定的规则，不是普通狼人杀的通用默认机制。

**有资格的自爆狼可以在自爆后的紧接着一晚，拥有一次最高优先级指刀权。**

资格要求：

- 下一夜开始时，仍有存活且夜间相认的红狼同伴。
- 自爆狼不是最后一名符合条件的普通狼人。
- 本次自爆不属于警上自爆吞毒。

具体操作：

| 情况 | 结算 |
|---|---|
| 自爆狼选择目标并确认 | 以自爆狼刀口为准 |
| 自爆狼主动确认空刀 | 当晚狼刀为空 |
| 其他狼人选择不同目标 | 无法覆盖自爆狼的最终决定 |
| 自爆狼未确认 | 回退到存活狼人正常投票 |
| 所有人都未投票 | 空刀 |
| 自爆狼确认完成 | 立即结束狼人阶段 |
| 自爆狼尚未确认 | 其他狼人不能提前结束 |
| 达到 180 秒 | 必须结算，不继续等待 |

自爆狼可以实时查看每名存活狼人的投票及修改情况。

存活狼人也能实时查看自爆狼当前选择的刀口。

这些信息只在狼队内部可见。

**指刀权仅持续自爆后的第一晚，不会持续到以后的夜晚。**

### 4.4 警上自爆吞毒

这是另一套特殊机制。

触发条件是：

**某狼人前一晚已经被女巫毒杀，但死亡尚未公布，并且该狼人在警长竞选期间自爆。**

已确认的规则：

| 情况 | 规则 |
|---|---|
| 触发位置 | 仅警长竞选阶段 |
| 第一天 | 可以触发 |
| 顺延到第二天的竞选 | 仍然可以触发 |
| 普通白天自爆 | 不能吞毒 |
| 女巫毒药 | 已使用，不返还 |
| 自爆狼死亡 | 只结算一次，不重复毒杀 |
| 是否公开吞毒 | 不公开 |
| 下一夜指刀 | 吞毒自爆狼不能参与 |
| 第一天吞毒遗言 | 90 秒 |
| 第二天及之后吞毒遗言 | 没有 |

例如第一晚：

狼人刀 7 号，女巫毒 3 号狼人，3 号警上自爆吞毒。

系统可以公布：

**「3 号、7 号玩家死亡，死亡顺序不分先后。」**

不会公开宣布「3 号吞毒成功」。

### 4.5 双爆吞警徽

第一次狼人自爆时，如果警长竞选尚未完成，竞选顺延到第二天。

第二名狼人再次自爆，且警长仍未选出时，警徽永久流失。

如果警长已经选出，第二次自爆不再触发吞警徽。

## 五、白天流程与警长竞选

### 5.1 第一天的流程

你已经特别确认过：

**第一天先进行警长竞选，再公布第一晚死讯。**

这是为了让已经中毒、但死讯尚未公布的狼人仍有机会警上自爆吞毒。

系统需要区分实际夜间死亡状态和对玩家公开的死亡状态。

### 5.2 警长竞选

| 阶段 | 已确认规则 |
|---|---|
| 上警报名 | 玩家自行选择上警或不上警 |
| 全员上警 | 警徽流失 |
| 警上发言 | 随机起始号码，每人 90 秒 |
| 退水 | 可以在发言期间及最终退水阶段退水 |
| 退水后 | 不能重新上警 |
| 无人留警 | 警徽流失 |
| 只剩一人 | 自动当选警长 |
| 多人留警 | 进入警长投票 |
| 第一轮投票 | 仅最初未上警的玩家参与 |
| 第一轮平票 | 最高票候选人进入 PK |
| PK 发言 | 每人 90 秒 |
| PK 投票 | 除 PK 候选人外，所有存活玩家可投 |
| 第二轮仍平票 | 警徽永久流失 |

特别注意：**退水玩家不能参加第一轮警长投票，但可以参加符合条件的 PK 投票。**

### 5.3 白天发言

我们确定支持两种发言模式。

**自动顺序发言**

每名玩家默认 90 秒。

发言玩家本人或房主，都能提前结束当前玩家的发言。

有警长时，警长决定递增或递减方向；没有警长则号码递增。

**自由发言**

系统只负责整个发言阶段，不逐人控制发言。

**由房主决定整个发言阶段什么时候结束。**

此前还确认过起始号码规则：无警长且前一夜单人死亡时，默认从死者之后较大的座位号开始；双死或平安夜则随机。实际使用时需要和当前板子的警长竞选、发言阶段衔接。

### 5.4 白天投票

| 功能 | 已确认规则 |
|---|---|
| 投票方式 | 手机投票或线下举手 |
| 方式选择 | 房主每轮投票前选择 |
| 手机投票 | 系统自动计票 |
| 线下投票 | 房主录入结果 |
| 默认时间 | 30 秒 |
| 自定义时间 | 每轮开始前可调整 |
| 全员提交 | 可以提前结束投票 |
| 超时未投 | 计为弃票 |
| 警长票 | 1.5 票 |
| 普通玩家 | 1 票 |
| 第一轮放逐平票 | 平票玩家 PK |
| PK 再平票 | 无人出局，进入下一夜 |

每轮投票开始前，房主还可以决定结果公开程度。

可以公开每个人的票型，也可以只公布汇总票数。投票进行期间不能提前泄露投票结果。

### 5.5 警徽管理

警长死亡时，可以将警徽转交给存活玩家，也可以撕掉警徽。

警徽移交没有强制倒计时。

如果公开流程卡住，房主可以经过二次确认接管，但不能因此获得查看秘密身份或操作夜间技能的权限。

## 六、死亡结算、遗言与胜负

这一块直接影响整个规则引擎。

### 6.1 死亡技能询问

**所有死亡玩家都必须经过统一的 10 秒死亡技能询问。**

公共语音统一播报：

> X 号玩家是否发动技能？

即使死亡的是平民、白痴或者不能开枪的猎人，也不能因为身份不同而省略这一环节。

没有成功发动技能时，统一等到 10 秒结束后播报未发动技能。

如果猎人可以开枪，成功发动后进入猎人线下指定目标、房主录入的流程。

### 6.2 遗言

| 死亡情况 | 是否有遗言 |
|---|---|
| 第一晚被狼刀 | 有 |
| 第一晚被毒杀 | 有 |
| 第二晚及之后死亡 | 无 |
| 白天被投票放逐 | 有 |
| 白天被猎人带走 | 有 |
| 第一晚猎人开枪带走 | 有 |
| 第二晚及之后猎人开枪带走 | 无 |
| 普通狼人自爆 | 无 |
| 第一天警上自爆吞毒 | 有 |
| 第二天及之后警上自爆吞毒 | 无 |

**遗言统一为 90 秒。**

玩家本人和房主都可以提前结束。

### 6.3 多人死亡与连锁死亡

同一晚多人死亡时，死亡处理顺序随机决定。

如果处理过程中猎人开枪带走新玩家，则新死者立即插入当前流程，优先处理完毕后再返回原队列。

每名死者的死亡技能和遗言最多处理一次。

### 6.4 胜负判定

这是你明确要求过的特殊优先级。

| 场景 | 结果 |
|---|---|
| 最后一神猎人死亡 | 狼人立即胜利，猎人不能开枪 |
| 最后一神女巫被狼刀，同时毒死最后一狼 | 狼人胜利 |
| 最后一民与最后一狼同夜死亡 | 狼人胜利 |
| 夜间产生多人死亡 | 先统一结算死亡，再检查胜负 |
| 白天产生死亡 | 每产生一名死者立即检查胜负 |
| 胜负已经确定 | 立即结束，不继续死亡技能、遗言或警徽移交 |

游戏结束后自动公布获胜阵营、全部玩家身份和完整对局记录。

## 七、房主控制、断线与隐私保护

这些功能不能被当成普通 UI 细节，因为它们会直接影响游戏公平性。

### 7.1 房主控制

| 功能 | 已确认规则 |
|---|---|
| 暂停游戏 | 原房主或临时房主均可 |
| 暂停确认 | 二次确认 |
| 暂停时长 | 不限制 |
| 暂停次数 | 不限制 |
| 暂停效果 | 冻结全部倒计时、技能、投票和阶段切换 |
| 恢复确认 | 二次确认 |
| 恢复准备 | 全员统一倒计时 5 秒 |
| 恢复后 | 继续原阶段及剩余时间 |
| 修改设置 | 暂停期间可修改未来阶段的非规则性设置 |
| 修改确认 | 批量修改后统一二次确认 |
| 设置通知 | 不主动通知玩家，进入对应阶段时展示新设置 |

不能在暂停期间修改玩家身份、胜利条件、核心技能规则或当前阶段倒计时。

原房主死亡后仍可以继续管理公开流程，也可以把临时管理权限交给其他存活玩家。

如果房主断线且没有临时房主，自动流程继续运行，需要房主操作时则等待房主恢复。

### 7.2 手机就绪与保持常亮

每晚开始前，默认要求所有玩家确认手机已就绪，包括已经死亡的玩家。

房主可以在开局前将其改为仅提醒模式。

强制模式下，如果有人一直未确认，房主可以查看未就绪座位，并经二次确认强制开始夜晚。

游戏期间默认尝试保持屏幕常亮，玩家可以自行关闭；游戏结束后释放常亮请求。

### 7.3 夜间隐私遮罩

所有玩家夜间看到一致的隐私遮罩和「查看操作」按钮。

只有轮到自己行动时，才可以进入对应技能界面。

玩家可以随时隐藏和重新打开未完成的技能界面。

手机锁屏、切换 App 后，自动恢复隐私遮罩。

返回游戏时同步服务器最新状态，不重置倒计时，未确认的选择在阶段有效期间保留。

### 7.4 断线重连

| 功能 | 规则 |
|---|---|
| 普通断线 | 不暂停游戏 |
| 宽限次数 | 每名玩家每局一次 |
| 宽限时长 | 15 秒 |
| 触发方式 | 系统根据断线和重连记录自动判断 |
| 非狼人角色 | 阶段结束前可以提供最多 15 秒宽限 |
| 尚未重连 | 仍等待最多 15 秒，超时跳过技能 |
| 阶段已经切换 | 不能补交技能 |
| 狼人夜间 | 严格不得超过 180 秒 |
| 房主权限 | 不能提前结束夜间重连宽限 |

为了防止泄露身份，公共设备统一播放：

> 系统连接异常，正在重新连接，请稍候……

不播报哪名玩家断线，也不播报相关角色。

## 八、手动记录器

这是我们后来确定的另一项核心功能。

### 8.1 记录方式

房主和 VIP 可以独立记录对局。

记录内容包括死亡玩家、死亡轮次、警徽变化、放逐结果、票型和个人推理。

**不采用共同编辑一份记录的方式。**

每位记录者维护自己的版本。

游戏过程中，这些记录不会自动展示给全体玩家。

### 8.2 手动模式

支持中途切换为纯手动记录模式，也支持手动记录与自动法官并行。

纯手动模式中，系统不再自动执行游戏阶段，但仍然知道线上确认过的全部身份。

房主和 VIP 记录死讯后，系统可以根据身份、板子胜利条件及有效死亡记录计算结果。

没有记录的信息必须显示「未记录」，不能自行补造。

### 8.3 官方结果与个人版本

房主记录用于正式胜负判定。

如果 VIP 记录与房主记录冲突，**官方结果以房主记录为准**。

VIP 可以发起结束申请，游戏进入待确认状态；房主可以拒绝、修正记录并恢复对局。

正式结束后，房主仍可以修正死讯，系统重新计算胜负，保留完整修订历史。

个人版本保持独立，不会被房主的修改覆盖。

### 8.4 赛后发布

房主和 VIP 可以分别发布自己的记录版本。

本局所有参局玩家都能查看已发布版本，并选择收藏。

记录者可以撤回自己的版本。撤回期间，收藏入口保留但不能访问；重新发布后恢复。

已发布记录可以保留独立草稿，只有主动发布新版本时才向收藏者同步。

历史版本可以查看。

## 九、账号、VIP、复盘与社交功能

这些不是首版自动法官必须全部实现的内容，但我们已经明确了主要设计。

### 9.1 账号与 VIP

普通玩家不需要注册就可以玩。

玩家可以在游戏中途登录，并关联当前及本设备可验证的历史对局。

登录用户可以保存昵称和头像。

头像上传默认限制为普通用户 **2 MB**、VIP **10 MB**，管理员可以调整。

VIP 必须绑定登录账号。

系统只有一个超级管理员，负责手动开通、取消和设置 VIP 有效期。

VIP 可以永久有效，也可以指定到期日期。

### 9.2 收藏和对外分享

| 功能 | 普通用户 | VIP |
|---|---|---|
| 游玩 | 支持 | 支持 |
| 查看有权限访问的复盘 | 支持 | 支持 |
| 收藏复盘 | 支持 | 支持 |
| 基础收藏管理 | 支持 | 支持 |
| 高级收藏搜索、筛选和命名 | 不支持 | 支持 |
| 生成对外分享链接 | 不支持 | 支持 |
| 管理自己创建的链接 | 不适用 | 支持 |

**房主不因为是房主就自动获得 VIP 权限。**

房主可以把自己的对局分享给本局参与者，但对外生成公开链接需要 VIP。

每名 VIP 只能撤销或重新生成自己创建的链接。

VIP 到期后，之前生成的链接自动暂停，重新开通后恢复；主动撤销的链接不会自动恢复。

已分享的官方复盘自动展示最新修订结果。

### 9.3 点赞和评论

对局点赞与评论点赞采用两套规则。

**对局点赞**：每个账号每天对同一局最多点赞一次，不可取消。所有复盘版本共用同一局的点赞次数。

**评论点赞**：每个账号对每条评论或回复只能点赞一次，不可取消。

同一局所有复盘版本共用评论区，支持多级嵌套回复。

评论排序支持最新、最热、最早，默认最新。

评论发表后，作者不能修改或删除；只有超级管理员可以删除违规内容。

### 9.4 通知与后台

通知中心包括复盘更新、评论回复、评论点赞和管理员通知。

通知保留 30 天，支持单条已读、全部已读、单条删除和清空。

评论点赞通知合并计数，评论回复逐条通知。

普通用户可以举报评论，每个账号对同一评论只能举报一次。

管理员可以审核举报、警告、临时禁言或永久禁止评论。

**进行中的隐藏身份、秘密行动和未公开私人笔记，即使是超级管理员也不能通过后台查看。**

# 十、对照当前 Codex 版本，我最关心的差异

虽然我们已经确认了很多功能，但不能要求 Codex 第一版全部实现。

我建议优先检查下面这些关键点：

| 优先级 | 检查项目 | 为什么重要 |
|---|---|---|
| P0 | 四位 OTP 房间号、选座、多人实时同步 | 所有功能的基础 |
| P0 | 两种发牌方式及身份保密 | 涉及游戏公平性 |
| P0 | 预女猎白夜间行动顺序及时间 | 核心玩法 |
| P0 | 狼人实时票型、确认和 180 秒限制 | 核心结算 |
| P0 | 警长竞选先于第一晚公开死讯 | 影响吞毒规则 |
| P0 | 自爆吞毒与自爆狼优先指刀 | 最容易实现错误 |
| P0 | 猎人、白痴及胜负优先级 | 影响最终胜负 |
| P1 | 白天发言、警长投票、PK、警徽 | 完整对局必需 |

## 十一、仍需要明确的流程问题

我们之前的规则非常详细，但整理之后，我认为还有三个需要在正式实现复杂规则前解决的衔接问题。

**第一，第一天警长竞选与胜负判定的优先级。**

我们同时规定了夜间死亡结算后检查胜负，以及第一天警长竞选先于公开死讯。

因此需要规定内部胜负检查具体发生在哪一刻，确保被毒狼人能够按规则完成警上自爆吞毒，同时不会错误延迟已经确定的终局。

**第二，警上自爆吞毒后的完整结算顺序。**

我们已经确定其他夜间死讯照常公布、自爆狼不重复毒杀、符合条件时有遗言，但还需要明确这些流程与尚未完成的警长竞选、其他死者死亡技能的先后关系。

**第三，自动模式切换为纯手动模式后如何恢复。**

我们已经确定可以切换，但尚未最终明确能否从纯手动重新切回自动法官，以及如何验证切换期间线下产生的所有技能和死亡状态。

这些地方不应该由 Codex 自行猜测。

## 我的建议

现在可以把这份清单作为 **Codex 的需求验收基线**。

开发顺序我建议是：

**第一阶段：** 创建房间、加入房间、选座、发牌、实时同步。

**第二阶段：** 完成预女猎白的一局自动法官，包括夜间技能、警长竞选、白天投票、死亡和胜负。

**第三阶段：** 补齐自爆吞毒、优先指刀、连锁死亡、暂停重连等特殊规则。

**第四阶段：** 手动记录、多版本复盘。

**第五阶段：** 账号、VIP、收藏、评论和后台。

**目前最重要的不是把所有功能做出来，而是让预女猎白能够从第一夜到游戏结束完整、正确地运行一局。**

等 Codex 的页面审查结果出来后，我们就能将这里的每项需求标记为「已实现 / 部分实现 / 未实现 / 存在冲突」，直接形成下一轮开发任务。
