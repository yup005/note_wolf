## 浏览器完整流程

1. **三个独立浏览器上下文**：房主创建、另两人四格入房、房主选座后二者更新、两人竞争同座、失败者改选空位，三台界面均显示 3/12；刷新保留座位；断网显示重新连接，回网显示实时同步并恢复当前座位。390px 页面无横向溢出，三页面没有 pageerror。
2. **OTP 与游客提示**：数字连续输入、空格位 Backspace 回退、粘贴以零开头的完整四位号、未知房间可见错误；同设备创建提醒仅接受一次，后续不重复弹出。前导零成功加入另由真实 HTTP `0042` 测试覆盖。
3. **容量**：12 个独立 browser contexts 的真实 HTTP 请求依次入房/占座；房主页面实时显示 12/12 和座位已满。该用例通过各上下文的 API 请求填满，不宣称 12 部真实手机逐台点击。
4. **重复创建回归**：浏览器拦截创建请求，将实际成功响应丢弃；刷新并重新点击创建；最终只有一个房间，房间 ID 与首次提交一致。
