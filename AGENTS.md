## Scope and safety
- Mobile-first in-person Werewolf app; prioritize iPhone Safari and preserve existing architecture/UI. Preserve the standard **12-player 预女猎白** (4 wolves, 4 villagers, one seer, witch, hunter, idiot). The owner authorized mechanical/armor development on 2026-10-10 and continued implementation before deployment on 2026-10-11. Confirmed mechanical/armor and custom-board flows are implemented locally; unresolved interactions remain explicitly blocked, and the separate any-player-count dual-category idiot policy is implemented locally as an explicit opt-in (14-player owner confirmation, 2026-10-12; player-count restriction removed, 2026-10-31), never inferred from headcount. Native black/white wolf kings and their mechanical/armor copies are implemented locally under the 2026-10-12 confirmed rules; see current rules and progress. Owner explicitly authorized the 12-player wolf-girl board on 2026-10-30; confirmed rules are WG-001–010 in docs/WEREWOLF_RULES_SPEC.md. Owner explicitly authorized the 12-player treasure-master board on 2026-11-01; confirmed rules TM-001–010 and current implementation boundaries are in docs/TREASURE_MASTER.md. 九尾/白泽 and other boards require explicit owner authorization; discussion docs alone do not authorize implementation. Owner explicitly authorized merging PR #8 and deploying the verified branch on 2026-10-30; see docs/RENDER_TRIAL.md for the running SHA and limited post-live verification. Future code delivery does not authorize another deployment or claim physical-device acceptance.
- Protect ongoing real-player identities, private skills/results and unpublished notes in every interface, log, speech cue and document. Ordinary hosts/admins gain no secret access; a current explicitly appointed publicly dead judge has the owner-confirmed game-secret exception, never access to other players' private notes (see current judge rules); test-only access is limited to simulated players and disabled in production by default. Owner confirmed a Render-trial exception on 2026-10-11: administrator-only independent simulated test rooms, after authorization/isolation implementation and verification. This exact-service exception was deployed and enabled under the owner's deployment request on 2026-10-25, with synthetic HTTP/Socket/admin/isolation checks (BETA-004); other production services remain disabled. See docs/RENDER_TRIAL.md for the deployed SHA and verification limits.
- Preserve user edits and useful history. Never invent unresolved gameplay, force-push, discard conflicting work, bypass checks/hooks or publish credentials/live data. Physical iPhone acceptance is separate from browser simulation.

Explicit newer confirmations supersede old wording; proposals/code alone do not resolve a rule. Ask when a required decision is missing.
3. Follow the [standing Git workflow](docs/CODEX_WORKFLOW.md#standing-git-workflow-preference-authorized-by-project-owner) and [progress requirements](docs/CODEX_WORKFLOW.md#maintain-progress-after-each-completed-task): publish by **completed feature, bug fix or documentation batch**. At the delivery boundary, run required checks, update docs/progress, review scoped diff, **automatically commit and push** on the current branch, verify the remote SHA and report GitHub links. No repeated commit/push reminder is needed. Never merge a PR without specific owner authorization.
4. For code/bugfix tasks run `npm test`, `npm run typecheck`, `npm run build`, plus applicable browser tests for UI changes; broad UI snapshots need full E2E. Documentation-only work uses document/link/diff checks and reports that code tests were not rerun. Stop publication when required checks fail or cannot run.
